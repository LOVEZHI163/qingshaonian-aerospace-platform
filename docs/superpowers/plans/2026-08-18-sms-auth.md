# 短信验证码登录与找回密码 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan.

**Goal:** 在保留密码登录和邮箱链接找回的前提下，为已注册且状态允许的账号增加短信验证码登录，完成短信验证码找回密码，并预留默认关闭的阿里云验证码 2.0 V3 接入。

**Architecture:** 把验证码生成、摘要、限流、过期、错误次数和一次性消费收敛到按 `purpose` 隔离的短信挑战服务；短信登录与短信找回复用这套底层，但分别使用 `sms-login`、`sms-password-reset` 两个用途和两个阿里云模板。密码登录与短信登录共用同一个服务端会话建立函数。阿里云验证码通过统一后端验证器与 Vue 前端门禁接入，功能开关默认关闭并且配置不完整时失败关闭。

**Tech Stack:** Node.js 20、Express、PostgreSQL、Vue 3、Vitest、Node test runner、Docker Compose、阿里云短信 SDK `@alicloud/dysmsapi20170525`、阿里云验证码 SDK `@alicloud/captcha20230305`。

## Global Constraints

- 短信验证码不得写入数据库明文或日志；数据库只保存 HMAC 摘要。
- 摘要输入必须包含 `purpose`、规范化手机号和验证码。
- 请求短信接口对存在、不存在和不可用账号返回同样的成功文案；限流和人机验证失败可以返回明确错误。
- 发送失败只能按本次 `digest` 删除挑战，不能按手机号批量删除。
- 短信登录只允许已注册、用户状态为 `active` 的账号；组织负责人还要求所属组织 `reviewStatus === "approved"` 且 `status === "active"`。
- `mustChangePassword` 不得被短信登录清除，登录后继续进入现有强制改密流程。
- 阿里云验证码 2.0 默认关闭；关闭时不加载远程验证码脚本，不调用验证码 API，不产生验证码费用。
- 开启验证码但缺少 Prefix、场景 ID 或服务端凭据时，相关发送接口必须返回稳定的 503，不能静默跳过；密码登录和其他业务仍可启动和使用。
- 线上第一阶段不得填写短信模板和验证码场景配置，不向用户显示尚未可用入口。

- [ ] **Step 5: 实现 `createSmsChallengeService`**

在 `apps/api/src/auth/sms-challenges.js` 导出不可变的 `SMS_PURPOSES`（`login: "sms-login"`、`passwordReset: "sms-password-reset"`）和 `createSmsChallengeService`。工厂参数固定包含 `purpose`、`secret`、`readDb`、`smsProvider`、`authState`、`resolveEligibleUser`、`verifyHuman`、`clock = Date.now`、`generateCode`、`logger = console`、`schedule = setImmediate`；返回对象固定包含布尔值 `enabled`、异步 `request` 和异步 `consume`。

摘要函数固定为：

```js
createHmac("sha256", secret)
  .update(`${purpose}:${phone}:${code}`)
  .digest("hex");
```

`request` 按“本地限流 → 人机校验 → 立即返回统一响应 → 后台读取账号 → 保存挑战 → 发送短信”执行。HTTP 路由不得等待账号查找、挑战写入或供应商发送，避免存在账号和不存在账号出现可观测时延差。后台任务必须捕获全部异常；发送失败只调用 `deleteChallenge({ purpose, phone, digest })` 条件删除本次挑战。`consume` 只消费指定用途的挑战并返回布尔值。

后台任务使用注入的 `schedule = setImmediate` 排队；`enabled` 固定代理 `smsProvider.enabled(purpose)`。未启用用途的 request 路由返回稳定 503，不排队后台任务，且 `/api/public/features` 对应开关为 false。

- [ ] **Step 3: 实现短信登录服务**

在 `apps/api/src/auth/sms-login.js` 导出 `createSmsLoginService`：

```js
export function createSmsLoginService({ challengeService, readDb, isEligible }) {
  return {
    enabled: challengeService.enabled,
    request(input) { return challengeService.request(input); },
    async confirm({ phone, code }) {
      const normalizedPhone = normalizePhone(phone);
      if (!await challengeService.consume({ phone: normalizedPhone, code })) throw invalidCode();
      const db = await readDb();
      const user = db.users.find((row) => normalizePhone(row.phone) === normalizedPhone);
      if (!isEligible(db, user)) throw invalidCode();
      return { db, user };
    }
  };
}
```
