# 温州市青少年航空航天创新比赛官网升级设计

## 1. 背景与目标

当前公共网站以单届赛事宣传页为主，已经具备赛事主视觉、时间地点、报名入口、赛项组别和简单新闻区域，但不足以承载长期品牌、多场同期赛事、官网内容发布和历届赛事归档。

本次升级将网站建设为“长期赛事品牌官网 + 报名服务中心 + 多届赛事内容平台”。设计吸收全国青少年安全与应急科普创新大赛官网的信息分层和公共服务入口优点，但保留本项目的航空航天视觉特征、现有报名业务和多角色管理体系。

主要目标：

- 使用长期名称“温州市青少年航空航天创新比赛”和用户提供的正式 SVG 商标、名称文件。
- 首页能够自适应同时存在 0、1、2、3 场进行中赛事。
- 管理员无需修改代码即可维护首页、赛事视觉、公告、新闻、优秀作品和历届内容。
- 报名、指南、成绩和证书形成统一的公共服务入口。
- 每场赛事拥有独立、可长期访问的详情页面。
- 保持现有 React 公共端、Vue 管理端、Node API、PostgreSQL 和服务器文件存储体系。

## 2. 非目标

- 不复制参考网站的图片、文案、Logo 或品牌元素。
- 不在本期引入独立第三方 CMS。
- 不重写现有报名、组织、成绩和证书业务。
- 不引入重型 3D 场景、自动播放背景视频或高成本沉浸式特效。
- 不在本期建设多语言官网。

## 3. 已选视觉方向

采用 A2“蓝底白字的官方赛事门户型”。

### 3.1 品牌规则

- 顶部导航使用蓝色背景，商标和正式名称 SVG 显示为白色。
- 白色或浅色背景中使用官方蓝色版本，不与黑色版本混用。
- 桌面端显示“商标 + 完整名称”，移动端按可用宽度等比缩放，极窄屏可仅保留商标并在菜单中显示完整名称。
- 商标保持原始比例和安全留白，不添加阴影、描边或品牌图形渐变。
- 主色为官方蓝、深蓝和白色；绿色仅用于“报名中、已发布”等正向状态，红色仅用于错误、截止或危险操作。

### 3.2 视觉气质

- 正式、可信、清晰，同时保留青少年航空航天的活力。
- 首屏使用真实航空航天主题图片和蓝白渐变遮罩，确保标题可读。
- 动效以轻量淡入、卡片位移和状态切换为主，并遵循 `prefers-reduced-motion`。
- 避免大面积空白、过度轮播和只为装饰存在的动画。

## 4. 多赛事首页规则

首页是平台主页，不固定绑定某一场赛事。

### 4.1 重点赛事选择

- 管理员可手动指定一场“首页重点赛事”。
- 没有手动指定时，系统自动选择处于报名期且报名截止时间最近的赛事。
- 手动指定的赛事不可展示时，自动回退到系统选择规则。

### 4.2 赛事数量适配

- 1 场进行中：重点赛事使用完整主视觉，不渲染空赛事卡片。
- 2–3 场进行中：一场重点赛事使用主视觉，其余赛事以同期赛事卡片展示。
- 0 场进行中：展示最近结束赛事的回顾主视觉，并引导进入历届赛事；不得显示虚假的“报名中”。
- 已归档赛事进入历届赛事列表，仍可访问独立详情页。

### 4.3 首页内容顺序

1. 蓝底白色品牌导航。
2. 重点赛事主视觉、状态、日期、地点、主按钮。
3. 同期赛事卡片（存在时）。
4. 报名中心、参赛指南、成绩查询、证书中心四个服务入口。
5. 平台公告与当前赛事公告。
6. 赛事动态、新闻、优秀作品。
7. 历届赛事入口。
8. 平台简介、主办单位、联系方式、备案信息。

## 5. 页面与路由

### 5.1 公共页面

- `/`：平台首页。
- `/events/:slug`：单场赛事详情。
- `/announcements`：公告列表。
- `/news`：新闻、优秀作品和赛事动态。
- `/history`：历届赛事。
- `/content/:slug`：公告或新闻详情。
- `/admin/`：沿用现有登录、报名和管理平台入口。

### 5.2 赛事详情页

每场赛事详情页包含：

- 赛事名称、主题、封面、状态、比赛时间、地点和报名截止时间。
- 报名按钮和报名开放状态。
- 赛事简介和主办信息。
- 规程、通知和附件下载。
- 赛项分类、个人赛/团体赛和适用组别。
- 绑定该赛事的公告、新闻和优秀作品。
- 赛后成绩查询和证书中心入口。

赛事基础字段、赛项和组别直接读取现有赛事数据，官网内容模块不重复维护业务事实。

## 6. 公共服务入口与权限

- 报名中心：未登录用户先进入登录/注册，登录后进入当前赛事报名。
- 参赛指南：公开访问，不要求登录。
- 成绩查询：登录后查看本人或本组织权限范围内的成绩。
- 证书中心：登录后预览、下载已发布证书。
- 管理员从统一登录入口进入管理后台。

首页按钮必须携带目标赛事上下文，存在多场赛事时不得默认将用户送入错误赛事。

## 7. 官网内容管理

管理端新增一级模块“官网内容”，保持与现有赛事、用户、报名和证书模块一致的界面风格。

### 7.1 首页设置

- 手动指定重点赛事。
- 调整同期赛事显示顺序。
- 维护平台简介、主办单位、联系方式和备案信息。
- 设置默认宣传图、分享封面和搜索摘要。

### 7.2 赛事视觉

- 每场赛事独立维护封面图、宣传语、摘要和详情页可见状态。
- 缺少封面时使用平台默认航空航天图片。
- 不复制赛事时间、地点、报名窗口、赛项或组别等现有业务数据。

### 7.3 内容发布

内容可归属平台或某一场赛事，类型至少包括公告、新闻、优秀作品和赛事回顾。

内容状态：

- 草稿
- 定时发布
- 已发布
- 已下线

同时支持置顶、封面图、摘要、富文本正文、附件、发布时间和排序。公共接口只返回已到发布时间的“已发布”内容。

### 7.4 媒体与归档

- 统一管理新闻图片、赛事照片、优秀作品和附件。
- 记录文件用途、所属内容、所属赛事、文件类型、大小和上传时间。
- 归档赛事仍可展示已发布内容。
- 清理历史资源时复用现有预检查、确认和审计流程，禁止删除仍被已发布内容引用的文件。

## 8. 数据边界

建议新增以下独立数据单元，具体表名可在实施计划中按现有数据库风格确定：

- 站点设置：品牌公共信息、默认资源、重点赛事和首页配置。
- 赛事公开资料：赛事封面、宣传语、摘要、公开可见状态和排序。
- 内容文章：归属范围、类型、标题、摘要、正文、状态、发布时间、置顶和排序。
- 媒体资源：文件元数据、引用关系、所属赛事和清理状态。
- 内容附件：文章与媒体资源之间的稳定关联。

报名、用户、组织、结果和证书继续由现有数据模型负责，官网模块只通过明确接口读取。

## 9. 数据流与发布流程

1. 管理员创建或编辑草稿。
2. API 校验字段、富文本、附件和资源引用。
3. 管理员在后台预览草稿。
4. 发布操作以事务方式更新发布状态和审计日志。
5. 公共 API 只返回已发布、未下线且满足发布时间的内容。
6. 公共 React 端按平台首页或赛事详情请求对应数据。
7. 下线内容立即从公共列表移除，但保留后台记录和审计信息。

新内容发布失败时，旧的已发布版本继续对外展示，不允许公共页面出现半写入状态。

## 10. 异常与空状态

- 无重点赛事：使用自动选择规则。
- 无进行中赛事：显示最近赛事回顾和历届入口。
- 无赛事封面：使用默认航空航天图片。
- 无公告或新闻：显示清晰空状态，不渲染空白大区块。
- 图片加载失败：使用固定比例的默认图，避免布局跳动。
- 单个内容接口失败：保留导航和主要服务入口，提供重试提示。
- 首页聚合接口失败：显示品牌、基础平台信息和友好维护提示，不白屏。
- 管理端发布冲突：提示内容已被其他操作更新，要求刷新后重新确认。

## 11. 安全与文件规则

- 官网内容写入接口仅允许管理员访问，并沿用现有会话、临时密码和审计规则。
- 富文本使用允许列表过滤，禁止脚本、事件属性、危险 URL 和未授权嵌入内容。
- 图片和附件按真实文件签名、扩展名、大小和 MIME 类型共同校验。
- 草稿资源不得通过公共资源地址访问。
- 已发布资源通过受控公共读取接口或明确的公开文件路径提供。
- 删除资源前检查引用关系；物理删除失败进入现有清理日志和重试机制。

## 12. 响应式、无障碍与 SEO

- 验收宽度：360px、768px、1440px、1920px。
- 导航在移动端切换为菜单，保留商标和报名入口。
- 所有主要操作支持键盘和可见焦点。
- 正文和背景达到基本对比度要求，状态不能只通过颜色表达。
- 图片提供替代文本；纯装饰图使用空替代文本。
- 页面标题、描述、分享封面、规范链接和站点地图由已发布内容生成。
- 公告和赛事详情使用稳定 slug，发布后修改标题不破坏原链接。

## 13. 性能目标

- 普通 4G 网络下首页主要内容约 2.5 秒内出现。
- 首页首屏资源尽量控制在 1.5MB 内。
- 上传图片生成适合桌面端和移动端的尺寸，优先使用 WebP，并保留必要的兼容格式。
- 首屏重点图优先加载，其余新闻、历届和画廊图片延迟加载。
- 避免自动播放视频和阻塞首屏的重型动画。

## 14. 测试与验收

### 14.1 自动化测试

- 0、1、2、3 场进行中赛事的首页聚合逻辑。
- 管理员手动指定重点赛事和自动回退逻辑。
- 平台内容与赛事内容的归属和筛选。
- 草稿、定时发布、已发布、已下线的公共可见性。
- 富文本过滤、文件真实性、大小边界和权限。
- 资源引用保护、下线、归档和清理。
- 公共端 API 失败、空状态和图片失败回退。
- 多赛事下报名按钮携带正确赛事上下文。

### 14.2 浏览器验收

- 桌面端和移动端品牌比例、导航、主视觉和服务入口。
- 首页信息层级、公告阅读、附件下载和赛事详情跳转。
- 普通用户、组织用户和管理员的登录后目标页面。
- 键盘导航、焦点、对比度和减少动态效果偏好。

### 14.3 发布验收

- API 和前端全量测试通过。
- 生产构建和部署配置检查通过。
- 数据库和上传目录备份完成。
- 阿里云容器健康、公共 smoke、认证 smoke 和线上浏览器验收通过。

## 15. 实施分解

该升级按一个设计、四个可独立验收阶段实施：

1. 官网内容数据、公共 API、管理员内容管理基础。
2. A2 蓝白品牌首页、多赛事聚合和赛事详情页。
3. 公告、新闻、优秀作品、历届赛事和媒体归档。
4. 响应式、无障碍、SEO、性能优化、全量测试和阿里云部署。

每个阶段必须保持现有报名、组织、成绩和证书功能可用，不以一次性重写方式替换线上系统。
