# AeroGP 测试站直接公开访问设计

## 背景

当前测试站在 Nginx 层启用了 HTTP Basic Auth。访问者必须先通过浏览器原生账号密码弹窗，才能看到网站主页。该保护给测试人员带来了两套账号的混淆：外层测试账号与应用内部手机号账号。

本次变更按用户选择，将测试站直接公开，让访问 `http://47.99.181.222` 时立即显示主页。

## 目标

- 移除浏览器原生账号密码弹窗。
- 主页、后台前端入口和公开 API 继续通过同一个 Web 入口访问。
- 保留应用内部的注册、登录、用户角色和后台权限校验。
- 保持 PostgreSQL 数据、API 容器和备份服务不变。
- 清理不再使用的外层认证配置和服务器凭据文件。

## 不在范围内

- 不移除应用内部登录。
- 不开放 PostgreSQL `5432` 或 API `4300` 到公网。
- 不接入域名、ICP备案或 HTTPS。
- 不重建数据库，不修改已有测试数据。

## 方案

### Web 入口

从 Nginx 配置中删除 `auth_basic` 和 `auth_basic_user_file`。`/healthz`、主页、`/admin/` 和 `/api/` 的现有路由保持不变。访问主页不再返回 `401`，而是直接返回前端页面。

### 容器配置

从 Web 服务中移除 `.htpasswd` 只读挂载，并删除 Web 启动时检查密码文件的入口脚本。Web 容器不再依赖外层认证文件，其余健康检查、日志轮转和端口映射保持不变。

### 凭据与脚本

服务器初始化脚本只生成 PostgreSQL 密码，不再生成 `BASIC_AUTH_USER`、`.htpasswd` 或 `/root/aerogp-test-credentials.txt`。远程冒烟测试改为无认证访问主页、后台入口和公开 API。

新配置验证成功后，删除服务器上已停用的外层认证文件。数据库 `.env` 继续保持 root-only 权限。

### 安全边界

站点内容将对互联网公开，搜索引擎和扫描器可能访问主页。应用内部受保护操作仍必须通过现有登录和角色权限；API 和数据库仍只在 Docker 内部网络通信。宿主机继续只监听 SSH `22` 和 HTTP `80`。

## 部署流程

1. 先修改配置验证测试，使其要求不存在 Basic Auth 配置，并观察测试按预期失败。
2. 最小化修改 Nginx、Compose、启动脚本、凭据脚本、冒烟测试和部署文档。
3. 运行 API 测试、生产构建、部署配置检查和 Compose 配置检查。
4. 上传新配置并重建 Web 容器；PostgreSQL 数据卷不重建。
5. 从公网验证 `/healthz`、`/`、`/admin/` 和公开 API 均无需认证即可访问。
6. 验证所有容器健康、宿主机没有公开 `4300` 或 `5432`，再清理停用的外层认证文件。

## 验收标准

- 无认证访问 `/` 返回 `200` 并包含主页标题。
- 无认证访问 `/admin/` 返回 `200`。
- 无认证访问 `/api/public/event` 返回 `200`。
- `/healthz` 返回 `200`。
- Web、API、PostgreSQL 和备份容器保持健康。
- PostgreSQL 数据与已有测试用户保持可用。
- 宿主机只监听预期的 `22` 和 `80` 端口。
- 服务器不再保留外层明文访问密码文件。
