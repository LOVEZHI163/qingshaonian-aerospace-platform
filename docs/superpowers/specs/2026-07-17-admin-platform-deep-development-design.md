# AeroGP 管理平台深度开发设计

## 背景

当前系统已经完成公开测试部署，并具备普通用户、组织用户、管理员、报名、成绩和证书等基础能力。现阶段管理员端仍集中在一个大型 Vue 页面中，赛事、赛项与组别主要来自固定种子数据；证书批量导入依赖 ZIP 内 PDF 文件名匹配，且数据库限制每条报名只能关联一张证书。

本次升级采用“保留现有 Vue、Node.js、PostgreSQL 和 Docker 架构，完成模块化升级”的方案。升级重点是管理员端、多届赛事管理、组织资质审核、完整报名管理以及 Excel 内嵌图片证书导入，同时修复注册表单状态串联问题。

## 目标

- 将管理员端拆分为清晰、可维护的业务模块。
- 支持多届赛事、赛项配置、报名时间和临时开放/关闭控制。
- 支持组织提交资质、管理员审核及组织成员管理。
- 完善报名搜索、筛选、刷新、审核、修改、成绩和完整导出能力。
- 使用 Excel 模板导入成绩和内嵌证书图片，不再解析证书 ZIP。
- 每条报名最多关联两张证书，支持修改、替换、删除、发布和撤回。
- 保留并安全迁移现有用户、组织、报名、成绩和证书数据。
- 增强会话认证、文件访问和危险操作的安全边界。

## 不在本次范围内

- 不更换现有前端、API、数据库和 Docker 技术栈。
- 不接入阿里云 OSS；测试阶段继续使用服务器持久化磁盘保存文件。
- 不建设复杂的多租户平台、任务队列或细粒度 RBAC 系统。
- 不改变网站首页的整体视觉设计，只使其读取当前赛事配置。
- 不支持旧版 `.xls` 证书模板，也不继续支持 ZIP 文件名匹配导入。

## 总体架构

系统保持三个主要层次：

1. Vue 管理端和用户报名端负责交互、表单校验、导入预览与状态展示。
2. Node.js API 负责会话认证、权限判断、业务校验、Excel 图片解析、文件保存和数据库事务。
3. PostgreSQL 保存业务数据和文件元数据，持久化磁盘保存资质、证书及导入文件。

管理员端不再把所有业务放在单个 `App.vue` 中，而是按后台概览、赛事、赛项与组别、组织、报名、证书、用户等模块拆分。通用筛选器、分页表格、文件预览、二次确认和批量选择抽成复用组件。

## 管理员端页面设计

### 后台概览

显示当前赛事、报名开放状态、报名数量、待审核组织、待审核报名、未发布证书和最近导入结果，并提供跳转到待处理事项的快捷入口。

### 赛事管理

赛事列表展示草稿、已发布和已归档赛事。管理员可以：

- 新建空白赛事。
- 复制上一届赛事及赛项配置，但不复制报名、成绩和证书。
- 设置唯一的当前赛事。
- 编辑赛事名称、主题、日期、地点、联系方式和首页介绍。
- 配置报名开始时间、截止时间和报名控制模式。
- 归档历史赛事、统计附件占用、清理大文件或彻底删除赛事。

报名控制模式为：

- `automatic`：按北京时间和报名起止时间自动判断。
- `force_open`：忽略时间，立即允许报名。
- `force_closed`：忽略时间，立即停止新增和用户修改报名。

管理员不受报名关闭限制，始终可以修正报名资料。彻底删除赛事必须输入完整赛事名称二次确认。

### 赛项与组别

每个赛项包含名称、项目类型、项目分类、允许组别、是否要求指导老师、显示顺序和启用状态。已产生报名的赛项不能硬删除，只能停用。

固定组别及映射为：

- 一至三年级：小学低段。
- 四至六年级：小学高段。
- 初一至初三：中学组。
- 普通高中和职高对应年级：职高/高中组。

用户填写实际年级，系统自动确定组别；报名页面只显示该组别允许报名的赛项。

### 组织用户管理

组织按待审核、已通过、已驳回和已停用筛选。管理员可以预览资质文件、通过、驳回、停用、重新启用、修改组织资料，并查看负责人、成员、报名数量及所属赛事。

组织详情页同时处理成员加入申请、成员移除和组织报名记录。统一社会信用代码必须唯一。

### 报名管理

报名列表支持：

- 按赛事、状态、组别、赛项和组织筛选。
- 按报名编号、姓名、学校、手机号和指导老师搜索。
- 手动刷新并显示最后刷新时间。
- 分页浏览，导出不受分页影响。
- 查看并修改实际年级、组别、组织关系、学校、赛项和指导老师。
- 通过、驳回、修改成绩及管理证书。

表格明确展示报名编号、姓名、学校、实际年级、组别、组织、赛项、指导老师、状态和成绩。取消证书编号输入框。

提供“导出筛选结果”“导出全部报名”和“导出证书模板”三个操作。完整报名导出包含报名来源、组织关系、联系方式、指导老师、审核状态、奖项、名次和成绩等全部字段；证书模板只包含已审核通过的报名。

### 证书管理

证书管理集中处理 Excel 导入预览、错误报告、未发布证书检查、单张或批量发布、批量撤回、修改、替换和删除。报名管理中的每条报名仍保留直接上传证书和修改成绩的快捷操作。

### 普通用户管理

保留现有用户查询和状态管理，并增加组织关系、报名记录和历史赛事关联查看能力。

## 注册与报名端调整

普通用户注册和组织用户注册使用两套独立的响应式表单状态，避免在左右表单中输入姓名或手机号时同步变化。

组织注册必填负责人姓名、手机号、密码、组织名称、统一社会信用代码和资质证明。资质证明允许营业执照、事业单位法人证书或办学许可证，文件格式支持 PNG、JPG、JPEG 和 PDF。组织注册后进入待审核状态，可以登录查看审核进度，但在通过前不能邀请成员、代报名或管理组织。驳回时显示原因，并允许修改后重新提交。

报名学校字段使用可搜索输入框，候选来源为已审核组织名称和历史报名学校名称；没有匹配项时允许手动填写。用户只有一个有效组织关系时自动关联该组织并预填学校；有多个有效关系时由用户选择。学校显示值可以修改，但真实组织关系单独保存。

## Excel 证书模板

模板格式为 `.xlsx`，每一行对应唯一报名记录，即“一个人加一个赛项”。同一个人报名两个赛项时，在模板中出现两行。

模板主要字段为：

`报名编号｜姓名｜学校｜年级｜组别｜赛项｜指导老师｜状态｜奖项/等级｜名次｜成绩/分数｜证书1名称｜证书1图片｜证书2名称｜证书2图片`

规则如下：

- 报名编号是唯一匹配依据，姓名、学校和赛项仅用于人工核对。
- 系统导出的报名资料列为只读提示列，管理员主要填写成绩及证书列。
- 每条报名最多两张证书，每张证书由名称和内嵌图片组成。
- 图片必须插入并锚定在对应报名行的证书图片单元格中。
- Excel 内嵌图片支持 PNG、JPG 和 JPEG。
- 不再填写或生成证书编号。
- 手动上传支持 PDF、PNG、JPG、JPEG 和 WebP。

## Excel 导入流程

1. 管理员选择赛事并导出已审核通过的证书模板。
2. 在 Excel 中填写奖项、名次、成绩、两组证书名称并插入图片。
3. 上传 Excel 后，API 解析报名编号、可编辑字段和图片锚点，只进行预检查，不立即写入正式数据。
4. 预览页分类显示有效记录、无效报名编号、缺少名称、缺少图片、图片格式错误和将要替换已有证书等结果。
5. 管理员确认后，在数据库事务中写入有效记录；错误记录跳过并生成可下载错误报告。
6. 所有导入证书均保存为未发布状态。
7. 管理员预览、修改并勾选证书后批量发布。

同一报名位置再次导入时，预览页明确标记“将替换证书1”或“将替换证书2”，未经确认不覆盖。导入批次记录操作者、原文件名、时间、成功数、失败数和错误详情。

用户下载证书时，系统根据姓名、赛项和证书名称生成可读文件名，例如 `张三_遥控纸飞机_一等奖.png`。

## 手动成绩与证书管理

管理员可以在报名详情中修改奖项/等级、名次和成绩/分数。每条报名提供证书位置1和证书位置2，并支持：

- 上传新证书。
- 预览或下载证书。
- 修改证书名称。
- 使用新文件替换原证书。
- 删除单张证书。
- 发布或撤回单张证书。

手动修改与 Excel 导入使用同一套数据模型，避免出现两套互不一致的证书记录。

## 数据模型

### 赛事与赛项

`events` 增加报名开始时间、报名截止时间、报名控制模式、发布状态、是否当前赛事、归档时间及创建更新时间。

`projects` 增加是否启用、是否要求指导老师和显示顺序。赛项与允许组别使用关联表保存，避免把多选值拼接为字符串。

### 组织资质

`organizations` 增加统一社会信用代码、审核状态、驳回原因、审核人、审核时间和更新时间。资质文件使用独立附件记录保存文件名、存储路径、MIME 类型、大小和上传时间。

### 证书

移除 `certificates.registration_id` 的单条唯一限制和业务上的证书编号，改为使用 `(registration_id, slot)` 唯一约束，`slot` 只能为 1 或 2。证书记录保存名称、文件信息、状态、上传来源、导入批次、发布时间和清理时间。

### 导入批次与操作日志

新增证书导入批次和导入错误记录，支持审计与错误报告。危险操作和关键审核写入操作日志，至少记录操作者、动作、对象、时间和摘要。

## 文件存储与清理

测试阶段继续使用 Docker 持久化卷，文件按用途和赛事分目录保存，数据库仅保存元数据。容器重建不能删除持久化文件。

归档赛事可以单独清理该赛事的证书和历史导入文件。组织资质不属于某一届赛事，按组织独立管理，只有组织已停用并由管理员单独确认时才允许清理。清理页面先展示文件数量和占用空间；确认后先更新数据库清理状态，再删除实际文件。清理后的证书保留名称、奖项和成绩，但显示“原文件已清理”，不再允许下载。

## 权限与安全

- 密码使用安全摘要存储，不再保存明文密码。
- 登录使用服务端会话，受保护 API 从会话读取用户身份，不接受前端传入用户编号作为授权依据。
- 密码找回同时支持两条路径：管理员在受保护后台为指定用户重置临时密码；普通用户通过本人手机号接收短信验证码后自助设置新密码。公开接口不得再使用“姓名 + 手机号”直接改密。
- 管理员重置和短信自助重置都必须递增用户的会话版本，使该用户已有会话立即失效；管理员重置后标记用户首次登录必须修改临时密码。
- 短信验证码为 6 位数字，有效期 5 分钟、单次最多验证 5 次、同手机号 60 秒内不可重复发送；验证码只保存 HMAC/摘要和失效时间，不保存明文，也不得写入日志。
- 短信发送按手机号和来源 IP 限流，申请接口使用统一响应避免泄露手机号是否注册。阿里云短信未配置时公开功能标记为关闭，管理员重置仍可独立使用。
- 新密码长度为 8–64 位，且至少包含一个字母和一个数字；登录和验证码接口均设置失败次数限制。
- 组织资质只有组织负责人和管理员可以访问。
- 未发布证书只有管理员可以访问。
- 已发布证书只有对应用户、所属组织和管理员可以访问。
- 上传时同时校验扩展名、MIME 类型、文件签名和大小，并对存储文件名做安全处理。
- Excel 解析设置行数、图片数和总体文件大小限制，防止超大工作簿占满服务器内存。
- 清理文件、批量发布和删除赛事等操作写入操作日志；危险操作要求二次确认。

## 数据迁移

部署升级前先备份 PostgreSQL 和上传文件目录。数据库迁移必须可重复执行，并在失败时终止应用升级。

迁移规则：

- 当前固定赛事转为第一届当前赛事。
- 现有项目关联到该赛事，并补齐启用状态和组别关系。
- 现有报名根据实际年级重新映射四个组别；无法判断的记录进入迁移报告，不静默猜测。
- 每条旧证书迁移到对应报名的证书位置1。
- 现有用户、组织、成员关系、成绩和报名状态全部保留。
- 旧明文密码在迁移或首次成功登录时转换为安全摘要，转换完成后不再回写明文。

迁移完成后验证记录数量、外键关系、证书文件存在性和测试账户登录。验证失败时保留旧容器和备份，停止切换流量。

## 错误处理

- 前端表单显示明确字段错误，不只展示通用失败提示。
- Excel 导入先预检查再确认，避免错误文件直接覆盖数据。
- 有效行可以导入，无效行跳过并生成错误报告；同一行内的成绩和证书更新保持原子性。
- 文件保存失败时不写入证书记录；数据库失败时清理本次产生的临时文件。
- 赛事关闭、项目停用或组织未审核等业务状态由 API 再次校验，不能只依赖前端按钮隐藏。
- 删除附件和赛事时提供明确影响范围，并记录成功或失败结果。

## 测试与验证

自动化测试至少覆盖：

- 两套注册表单状态完全隔离。
- 组织资质注册、审核、驳回、重提和权限控制。
- 报名时间边界及自动、临时开放、临时关闭三种模式。
- 四类年级到组别映射和赛项组别限制。
- 组织自动匹配、学校搜索和手动学校输入。
- 报名筛选、刷新、指导老师显示和完整 Excel 导出。
- Excel 内嵌一张或两张图片的预检查、导入、替换、错误报告和重复导入。
- 手动上传 PDF 或图片、修改、删除、发布、撤回和下载权限。
- 多届赛事复制、切换、归档、附件清理和危险删除。
- 旧数据库迁移、文件迁移、备份恢复和 Docker 重启后数据持久化。

部署到测试服务器后执行浏览器端到端验证，并从普通用户、组织负责人和管理员三个角色分别走通主要流程。

## 验收标准

- 在普通注册表单中输入姓名或手机号，不再影响组织注册表单，反向操作同样成立。
- 组织必须提交统一社会信用代码和资质证明，经管理员审核后才能使用组织功能。
- 管理员可以管理多届赛事、赛项、四个组别和报名三态开关。
- 报名页面自动匹配组织、支持学校搜索，并按年级自动确定组别。
- 报名管理显示指导老师，支持刷新、完整查询和完整 Excel 导出。
- 证书模板一行对应一条报名，支持两组内嵌证书图片，不依赖 ZIP 或证书编号。
- 导入证书默认为未发布，管理员检查后可以批量发布。
- 管理员可以手动上传 PDF 或图片，修改、替换和删除任一证书，并修改成绩。
- 历史赛事可以归档和清理大文件，文字记录仍可查询；彻底删除需要输入赛事名称确认。
- 升级后现有测试用户、组织、报名、成绩和证书数据保持可用。
- API 权限不再依赖前端提交用户编号，资质与证书文件不会被未授权访问。
