# 图像视频作品提交与服务器存储管理设计

日期：2026-07-31
状态：设计已批准，待实施
适用系统：赛事官网、普通用户端、组织端、赛事管理平台、API 与部署环境

## 1. 背景

系统当前已经支持多赛事、赛项、报名、组织用户、成绩、证书和官网内容，但所有赛项均默认只提交结构化报名信息。美术绘画等特殊赛项还需要提交两份参赛材料：

1. 一张作品正面高清图片；
2. 一段本人连续作画视频。

当前文件上传主要面向组织资质、证书和官网图片，单文件上限较小，并且部分接口使用内存缓冲。现有 Nginx 全局请求上限为 30MB，不适合最大 200MB 的视频。赛事管理平台也缺少服务器磁盘概览、分类占用统计、批量下载和批量清理能力。

线上赛事设置和组织审核页面目前还出现了整段 Express HTML 404 错误。排查已经确认：生产服务器加载的后台脚本为旧构建包 `index-D5LaGtnH.js`，当前分支构建入口为 `index-C_ECuZcQ.js`。旧包仍请求已经废弃的 `/api/admin/registrations`，而当前 API 只保留显式赛事范围的 `/api/admin/events/:eventId/registrations`。根因是线上 Web 与 API 发布版本不一致，不是赛事或组织数据损坏。

## 2. 已确认的业务决策

### 2.1 赛项提交类型

赛项只提供两种作品提交类型：

- `无需上传`
- `图像视频作品`

选择“图像视频作品”后，作品图片与作画视频均为必传。现有赛项默认“无需上传”，不改变普通赛事报名流程。

### 2.2 图片规则

- 必须为 JPG 或 PNG；
- 文件不得超过 2MB；
- 服务端检查真实文件签名，不能只检查扩展名或浏览器 MIME；
- 建议长边不低于 780 像素；
- 长边不足 780 像素只显示警告，不阻止报名；
- 正面平拍、四边完整、光线均匀、无明显透视变形、不得美化调色、拼接、滤镜、水印或文字等内容要求由管理员人工审核。

### 2.3 视频规则

- 必须为 MP4；
- 文件不得超过 200MB；
- 时长不得超过 2 分钟；
- 建议分辨率不低于 720P；
- 低于 720P 只显示警告，不阻止报名；
- 固定机位、连续拍摄、不得剪辑变速或叠加特效、须清晰呈现本人、画纸和连续作画动作等内容要求由管理员人工审核。

### 2.4 修改和审核

- 待审核、已驳回报名允许普通用户替换自己的材料；
- 已通过报名不允许普通用户自行替换；
- 组织管理员可以直接替换本组织报名的图片和视频；
- 组织管理员替换已通过报名的任何材料后，报名自动恢复为待审核；
- 平台管理员可以查看、下载、替换、审核和清理材料；
- 作品审核与现有报名审核合并，不建立独立的第二套审核状态；
- 清理实体文件不自动改变报名审核状态，但界面必须明确显示“文件已清理”。

### 2.5 存储方向

测试阶段继续使用 ECS 持久化磁盘和现有 `uploads_data` 命名卷。大文件必须流式写入，不能整体放入 Node.js 内存。存储服务保留抽象边界，使以后迁移到阿里云 OSS 时不改变报名、审核和权限模型。

## 3. 目标

1. 在赛项级别启用图像视频作品提交，不依赖赛项名称硬编码。
2. 普通用户和组织管理员都能完成两份必传材料的可靠上传。
3. 对格式、大小和时长执行强制校验，对建议尺寸和分辨率给出可见警告。
4. 平台管理员在报名管理中统一预览、审核、下载和替换作品材料。
5. 组织管理员替换已通过作品后自动触发重新审核。
6. 在赛事管理平台概览中展示服务器和存储状态。
7. 支持按文件分类筛选、批量下载和批量清理。
8. 清理后保留业务元数据和审计记录，并安全回收磁盘空间。
9. 修复线上 Web/API 版本不一致及原始 HTML 错误直接暴露问题。
10. 保持现有多赛事数据隔离、报名去重、证书和组织权限规则不变。

## 4. 非目标

本次不包含：

- 自动识别视频是否剪辑、变速或替换画面；
- 自动判断图片是否调色、美化、拼接、带滤镜、水印或文字；
- 自动判断视频中是否完整出现参赛者本人和画纸；
- 在当前阶段直接接入阿里云 OSS；
- 支持管理员自由创建任意数量、任意格式的动态材料字段；
- 将作品图片或视频公开到官网；
- 为组织设计额外的协管员角色；
- 在浏览器中进行大型视频编辑、转码或剪辑。

## 5. 总体方案

采用“赛项级固定作品模式 + 可扩展材料记录”的方案：

1. 赛项保存 `submissionMode`，当前只允许 `none` 和 `image_video`。
2. 图像视频赛项固定要求 `artwork_image` 与 `creation_video` 两类材料。
3. 文件先进入受账号和赛项约束的临时上传会话。
4. 两份材料均完成强制校验后，才允许正式提交报名。
5. 正式提交在一个数据库事务中创建或合并报名，并绑定两份材料。
6. 替换文件采用“先保存新文件、再切换数据库引用、最后清理旧文件”的顺序。
7. 文件元数据进入 PostgreSQL，实体文件进入 `UPLOAD_ROOT` 对应的持久化卷。
8. 所有读取均经过权限接口，不暴露直接磁盘路径或公共静态 URL。

## 6. 数据模型

### 6.1 赛项

在 `projects` 增加：

```text
submission_mode
```

允许值：

- `none`
- `image_video`

数据库默认值为 `none`，因此迁移后所有历史赛项行为不变。

API 和前端显示名称分别映射为：

- `none` → 无需上传
- `image_video` → 图像视频作品

### 6.2 临时上传会话

新增 `registration_upload_sessions`，至少包含：

- `id`
- `event_id`
- `project_id`
- `owner_user_id`
- `organization_id`，个人上传时可为空
- `state`：`active`、`committed`、`expired`
- `created_at`
- `expires_at`
- `committed_at`

会话必须绑定当前账号、赛事和赛项。不能把一个赛事或一个账号创建的临时文件提交到另一个赛事或账号。

临时会话默认在 24 小时后过期。过期任务只处理未提交会话，已绑定正式报名的材料不能被临时清理任务删除。

### 6.3 作品材料

新增 `registration_submission_assets`，每条当前报名最多有两类有效材料：

- `artwork_image`
- `creation_video`

记录至少包含：

- `id`
- `registration_id`，正式绑定前可为空
- `upload_session_id`
- `kind`
- `original_name`
- `stored_name`
- `file_path`
- `mime_type`
- `size_bytes`
- `width`
- `height`
- `duration_ms`，图片为空
- `uploaded_by_user_id`
- `uploaded_at`
- `cleaned_at`
- `cleanup_reason`

约束：

- 正式报名的同一种 `kind` 只能有一份当前材料；
- 文件被清理后保留整条记录，仅填写 `cleaned_at`；
- 替换时更新当前材料引用，旧文件元数据写入审计日志；
- 实体文件删除失败时写入现有 `file_cleanup_journal`。

### 6.4 审计日志

新增或复用以下动作类型：

- `registration_asset_upload`
- `registration_asset_replace`
- `registration_asset_download`
- `registration_asset_preview`
- `registration_asset_cleanup`
- `registration_asset_batch_download`
- `registration_asset_batch_cleanup`
- `registration_review_reset_after_asset_replace`

日志记录操作人、赛事、报名、组织、材料类型、文件大小、旧新材料标识和时间。日志不保存视频或图片内容。

## 7. 上传流程

### 7.1 普通用户新报名

1. 用户选择赛事、组别和赛项。
2. 普通赛项继续使用现有 JSON 报名流程。
3. 图像视频赛项创建临时上传会话。
4. 页面分别上传作品图片和作画视频。
5. 服务端逐项返回强制校验结果、元数据和建议项警告。
6. 两项均完成且未被清理后，启用“提交报名”按钮。
7. 正式提交时服务端再次检查会话归属、赛项模式和两份材料。
8. 在一个事务中创建或合并报名并绑定材料。
9. 提交成功后会话变为 `committed`。

如果创建或合并报名失败，临时材料仍保留到会话过期，用户可以修正报名数据后重试，不需要重复上传已经合格的文件。

### 7.2 组织管理员报名

组织端使用同一上传会话和校验接口，但会话还必须绑定组织：

- 当前账号必须是该组织唯一负责人；
- 组织必须已经加入当前赛事；
- 报名必须归属该组织；
- 不能利用上传会话替其他组织写入材料。

### 7.3 替换材料

替换图片或视频时：

1. 新文件先写入新的随机路径；
2. 完成签名、大小、图片尺寸或视频元数据校验；
3. 数据库事务切换当前材料引用并写入审计日志；
4. 如果报名原为已通过，组织管理员替换后将报名重置为待审核并清空旧驳回原因；
5. 数据库提交后再删除旧实体文件；
6. 删除失败写入清理日志，不回滚已经生效的新文件。

普通用户不能替换已通过报名。平台管理员替换时也必须产生审计记录；如内容发生变化，报名恢复待审核，管理员可随后重新审核。

## 8. 文件校验与存储

### 8.1 图片

服务端执行：

1. 流量和文件大小上限检查；
2. 文件真实签名检查；
3. 只接受 JPEG 和 PNG；
4. 使用图片解析器读取宽高并自动纠正 EXIF 方向；
5. 超过 2MB 或解析失败时拒绝；
6. 长边不足 780 像素时返回 `warning`，但保留文件。

不对参赛原图进行美化、压缩或转码，审核和下载均使用原始文件。

### 8.2 视频

视频不得使用 `multer.memoryStorage()`。上传中直接写入受控临时目录，并同时限制累计字节数。

服务端执行：

1. 最大 200MB 强制限制；
2. MP4 容器和真实文件类型检查；
3. 使用视频元数据工具读取时长、宽度和高度；
4. 时长超过 120 秒时拒绝并删除临时文件；
5. 分辨率低于 720P时返回 `warning`，但允许提交；
6. 元数据读取失败、伪造格式或损坏文件直接拒绝。

视频不自动转码。私有播放接口支持 HTTP Range，允许浏览器拖动播放进度而不重复下载整个文件。

### 8.3 磁盘保护

服务端使用上传卷的真实文件系统统计，而不是只读取数据库累计值：

- 使用率达到 80%：赛事管理平台显示黄色预警；
- 使用率达到 90%：显示红色预警并暂停新的视频上传；
- 每次视频上传前同时检查可用空间和安全保留量；
- 上传中超过限制、连接中断或校验失败时删除未绑定的临时文件；
- 磁盘状态接口只向平台管理员开放。

## 9. 前端体验

### 9.1 报名表

选择图像视频赛项后显示两个独立上传卡片。

图片卡片展示：

- 文件名；
- 缩略图；
- 格式；
- 尺寸；
- 文件大小；
- 建议项警告；
- 重新选择和替换操作。

视频卡片展示：

- 文件名；
- 上传进度；
- 时长；
- 分辨率；
- 文件大小；
- 建议项警告；
- 播放、重新选择和替换操作。

图片和视频分别上传，某一项失败时只重新上传该项。两项均通过前，“提交报名”保持禁用并明确指出缺少的材料。

### 9.2 普通用户报名记录

报名详情显示：

- 图片与视频状态；
- 预览和下载入口；
- 管理员驳回原因；
- 待审核、已驳回时的替换入口；
- 已通过时的只读提示；
- 被平台管理员清理后的“实体文件已清理”状态。

### 9.3 组织赛事工作台

组织报名和报名记录均显示作品材料状态。组织管理员可以：

- 上传；
- 预览；
- 下载；
- 直接替换本组织报名的图片或视频。

替换已通过材料后，页面立即显示报名已恢复为待审核。

## 10. 平台管理员审核

“报名管理”列表新增“作品材料”列，状态包括：

- 无需作品；
- 待上传；
- 已齐全；
- 有警告；
- 图片已清理；
- 视频已清理；
- 文件缺失或损坏。

管理员进入报名详情后可以：

- 查看高清图片；
- 播放视频；
- 查看大小、尺寸、分辨率、时长、上传者和上传时间；
- 下载原文件；
- 替换材料；
- 通过报名；
- 填写原因后驳回报名。

技术强制校验不通过的材料不能绑定正式报名。人工内容规则由管理员在同一个报名审核动作中判断，不建立额外作品审核状态。

## 11. 服务器概览与分类管理

### 11.1 概览

赛事管理平台“概览”增加“服务器与作品存储”，展示：

- API 状态；
- 数据库状态；
- 文件存储状态；
- 磁盘总容量、已用容量、剩余容量和使用率；
- 系统内存使用概览；
- 最近数据库备份时间；
- 最近上传文件备份时间；
- 最近清理时间及释放空间。

存储分类：

- 作画视频；
- 作品图片；
- 证书文件；
- 官网图片及附件；
- 组织资质文件；
- 临时上传和失败残留。

每类显示有效文件数、已清理数和实体文件占用空间。

### 11.2 分类详情

分类详情支持按以下条件筛选：

- 赛事；
- 赛项；
- 文件类型；
- 上传时间；
- 报名审核状态；
- 文件是否已清理。

图片与视频分开管理、分开选择、分开下载与清理，不允许在同一批操作中混合。

### 11.3 批量下载

- 管理员勾选文件后发起批量下载；
- 服务端直接流式生成压缩包，不先在服务器复制一份完整压缩文件；
- 压缩包包含文件和一份清单，清单记录赛事、报名编号、姓名、组织、赛项、文件类型及原文件名；
- 单批总大小和文件数量设置安全上限；
- 超过上限时，页面自动拆分为多个下载批次；
- 已清理或实体缺失文件不能加入下载批次，并在批次预检查中明确列出。

### 11.4 分类清理

管理员选择同一分类中的文件后，清理弹窗展示：

- 文件数量；
- 总大小；
- 关联赛事和报名数量；
- 预计释放空间；
- 已发布证书、当前组织资质或仍被官网引用的文件等风险提示。

管理员点击一次明确的“确认清理”按钮即可，不要求勾选声明或输入报名编号。

分类安全规则：

- 作品视频和作品图片：可由平台管理员清理实体文件，报名和审核状态保留；
- 证书：允许清理，但已发布证书必须显示显著影响提示，清理后用户无法下载；
- 官网媒体：只能清理未被首页、赛事视觉、正文或附件引用的文件；
- 组织资质：只能清理历史或已替换文档，启用组织的当前资质文件不可清理；
- 临时上传：只能清理已过期或明确失败的会话文件。

清理完成后：

- 数据库保留元数据并写入 `cleaned_at`；
- 写入审计日志；
- 删除实体文件；
- 删除失败写入 `file_cleanup_journal`；
- 立即刷新分类统计和磁盘使用率；
- 前端显示“已清理”，不能显示为“未上传”。

## 12. 权限

### 12.1 普通用户

可访问：

- 自己报名的作品材料；
- 待审核、已驳回报名的上传和替换；
- 自己材料的预览和下载。

不可访问：

- 其他用户材料；
- 已通过报名的替换；
- 服务器状态；
- 分类管理和清理。

### 12.2 组织管理员

可访问：

- 自己唯一负责组织在已加入赛事中的报名材料；
- 上传、替换、预览和下载；
- 已通过报名的替换，但替换后自动恢复待审核。

不可访问：

- 其他组织材料；
- 平台级服务器状态；
- 分类批量清理；
- 文件清理日志的管理操作。

### 12.3 平台管理员

可访问全部赛事材料、服务器概览、分类下载、分类清理、审核和审计日志。

所有文件端点在返回文件前必须重新校验账号、赛事、报名和组织归属，不能只依赖前端隐藏按钮。

## 13. API 边界

接口遵循现有显式赛事范围，示意如下。

### 13.1 赛项设置

```text
POST  /api/admin/events/:eventId/projects
PATCH /api/admin/projects/:projectId
```

请求和响应包含 `submissionMode`。

### 13.2 上传会话与材料

```text
POST   /api/me/events/:eventId/projects/:projectId/upload-sessions
POST   /api/organization/events/:eventId/projects/:projectId/upload-sessions
PUT    /api/upload-sessions/:sessionId/artwork-image
PUT    /api/upload-sessions/:sessionId/creation-video
DELETE /api/upload-sessions/:sessionId/assets/:kind
```

上传接口返回元数据、强制校验状态和建议项警告。会话归属在每次请求中验证。

### 13.3 正式报名与替换

现有报名创建接口增加 `uploadSessionId`：

```text
POST /api/me/events/:eventId/registrations
POST /api/organization/events/:eventId/registrations
```

替换接口显式包含赛事和报名：

```text
PUT /api/me/events/:eventId/registrations/:registrationId/assets/:kind
PUT /api/organization/events/:eventId/registrations/:registrationId/assets/:kind
PUT /api/admin/events/:eventId/registrations/:registrationId/assets/:kind
```

### 13.4 私有查看与下载

```text
GET /api/me/events/:eventId/registrations/:registrationId/assets/:kind
GET /api/organization/events/:eventId/registrations/:registrationId/assets/:kind
GET /api/admin/events/:eventId/registrations/:registrationId/assets/:kind
```

视频端点支持 Range。响应使用安全文件名、`nosniff` 和私有缓存策略。

### 13.5 平台存储管理

```text
GET  /api/admin/system/storage-summary
GET  /api/admin/storage-assets
POST /api/admin/storage-assets/batch-download-plan
POST /api/admin/storage-assets/batch-download
POST /api/admin/storage-assets/batch-cleanup
POST /api/admin/storage-assets/cleanup-expired
```

批量操作必须在服务端重新应用分类、权限和清理资格规则，不能信任前端提交的文件路径。

## 14. 线上版本错误修复

### 14.1 发布版本一致性

API 与 Web 构建时嵌入同一个发布标识，例如 Git commit：

- API 提供只读版本端点；
- 管理后台编译产物保存相同版本；
- 后台启动时比较两个版本；
- 不一致时停止高风险管理操作，并提示“系统版本不一致，请刷新或联系管理员”。

部署脚本必须校验：

1. 服务器 `.release`；
2. API 返回的发布标识；
3. `/admin/index.html` 引用的实际资源文件；
4. 资源文件存在且来自当前构建；
5. 赛事设置、组织审核和报名管理不再请求旧 `/api/admin/registrations`。

### 14.2 前端错误归一化

API 客户端按响应 `Content-Type` 解析：

- JSON 错误继续显示服务端业务消息；
- HTML、纯文本代理错误或无法解析的响应不直接呈现原文；
- 统一显示简洁错误和 HTTP 状态；
- 开发日志保留必要诊断信息，但不得向用户暴露整段 HTML、堆栈或内部路径。

### 14.3 缓存

- `/admin/index.html` 保持 `no-store`；
- 带内容哈希的 JS/CSS 继续使用长期 immutable 缓存；
- 部署后通过实际页面资源引用验证新入口已生效；
- 不能只根据容器健康或 `.release` 文件判断 Web 已更新。

## 15. 部署调整

### 15.1 Nginx

- 普通接口保持现有较小请求上限；
- 只对作品视频上传路径提高到约 205MB；
- 视频上传路径关闭代理整包缓冲，允许流式传给 API；
- 上传、下载和 Range 播放设置合理超时；
- API 与 PostgreSQL 继续不直接暴露公网端口。

### 15.2 API 镜像

- 加入可靠的视频元数据检测工具；
- 使用磁盘型临时存储和随机文件名；
- 对上传中断、格式错误、超时和磁盘不足执行清理；
- 容器继续挂载现有 `uploads_data:/data/uploads`。

### 15.3 备份与回滚

上线前必须：

1. 验证数据库备份；
2. 验证完整上传卷备份；
3. 记录旧 API/Web 镜像；
4. 验证磁盘剩余空间；
5. 确认四个服务健康。

部署采用同一源码提交构建 API 和 Web。禁止执行 `docker compose down -v`，禁止删除数据库卷和上传卷。

回滚时优先恢复旧 API/Web 镜像并保留新数据卷；只有确认迁移不兼容或数据损坏后，才使用已验证备份恢复。

## 16. 错误处理

- 图片格式、大小或解析失败：拒绝该图片，保留会话中的合格视频；
- 视频格式、大小、时长或解析失败：拒绝该视频，保留会话中的合格图片；
- 磁盘不足：在写入前拒绝，上传中检测到空间不足时删除不完整文件；
- 上传断开：会话保持可重试，残留文件由过期任务处理；
- 正式提交失败：合格临时材料保留到会话过期；
- 替换数据库失败：删除新文件，保留旧文件和旧引用；
- 替换后旧文件删除失败：新文件生效，旧文件进入清理日志；
- 下载中断：不创建额外服务器副本，用户可重新下载；
- 批量清理部分失败：逐项返回成功和失败明细，失败项保留或进入清理日志；
- 物理文件意外缺失：保留元数据，标记“文件缺失”，不得伪装为未上传。

## 17. 测试范围

### 17.1 API

- 历史赛项默认 `none`；
- 图像视频赛项必须两项齐全；
- 图片格式、真实签名、大小和尺寸规则；
- 视频格式、真实元数据、大小、时长和分辨率规则；
- 会话跨账号、跨组织、跨赛事和跨赛项访问全部拒绝；
- 普通用户、组织管理员、平台管理员的读取和替换权限；
- 组织管理员替换已通过材料后状态恢复待审核；
- Range 播放；
- 磁盘 80% 和 90% 行为；
- 临时上传过期清理；
- 分类批量下载和清理；
- 被引用官网媒体和当前组织资质不可误删；
- 文件删除失败进入清理日志；
- 旧 `/api/admin/registrations` 保持不可用，所有生产代码使用赛事范围接口。

### 17.2 前端

- 普通赛项不显示上传区；
- 图像视频赛项显示两项必传；
- 上传进度、失败重试、警告和提交按钮状态；
- 普通用户已通过后只读；
- 组织管理员替换及自动待审核提示；
- 管理员预览、审核和驳回原因；
- 概览磁盘状态和分级预警；
- 分类筛选、多选、下载批次和清理确认；

### 17.3 部署验证

- API、Web、PostgreSQL、Backup 均健康；
- API/Web 发布标识一致；
- 管理后台实际加载当前构建资源；
- 赛事设置、组织审核、报名管理无旧接口请求；

## 18. 验收标准

1. 管理员能把任一赛项设置为“无需上传”或“图像视频作品”。
2. 图像视频赛项缺少任一材料时不能提交报名。
3. 图片和视频强制规则、建议警告与人工审核边界符合已确认要求。
4. 普通用户与组织管理员权限符合设计，组织替换已通过材料后自动待审核。
5. 平台管理员能在报名管理中完成预览、下载、替换、通过和驳回。
6. 概览能显示真实磁盘容量、分类占用和分级预警。
7. 图片、视频、证书、官网媒体、组织资质和临时文件能分类管理。
8. 批量下载采用流式压缩，批量清理只需一次明确确认。
9. 清理后业务元数据、审核结果和审计记录保留，实体空间得到释放。
10. 线上后台不再显示原始 HTML 404，Web/API 版本不一致能够被发布检查发现。
11. 现有普通赛项、多赛事、组织、报名、证书和官网功能回归测试通过。
