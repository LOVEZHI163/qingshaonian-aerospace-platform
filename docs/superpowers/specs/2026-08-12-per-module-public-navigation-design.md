# 官网分栏目抽屉导航与头部视觉优化设计

日期：2026-08-12

## 1. 目标

将官网目前所有一级导航共用的全宽大抽屉，改为与一级栏目一一对应的紧凑子抽屉，并同步优化网站头部的视觉层级、对齐关系和登录报名入口。

本次同时统一前台和后台的内容类型显示名称：

- “赛事公告”统一显示为“通知公告”；
- “赛事动态”统一显示为“新闻动态”；
- “赛事回顾”保持名称不变。

数据库内部类型值继续使用 `announcement`、`news`、`recap`，已有文章和网址不迁移、不丢失。

## 2. 信息架构

### 2.1 一级导航

桌面端头部从左到右为：

1. Logo 与平台名称；
2. 首页；
3. 关于大赛；
4. 赛事资讯；
5. 获奖查询；
6. 联系我们；
7. 用户登录；
8. 报名入口。

### 2.2 分栏目子抽屉

只有前三个一级栏目具有子抽屉：

| 一级栏目 | 子项 | 目标页面 |
| --- | --- | --- |
| 首页 | 赛事服务 | 首页赛事服务区 `/#services` |
| 首页 | 报名流程 | `/registration-guide` |
| 首页 | 关于大赛 | `/about` |
| 关于大赛 | 赛事简章 | `/about` |
| 关于大赛 | 赛事章程 | `/rules` |
| 赛事资讯 | 通知公告 | `/announcements` |
| 赛事资讯 | 新闻动态 | `/news` |
| 赛事资讯 | 赛事回顾 | `/history` |

赛事相关公开页面继续携带当前赛事的 `event` 查询参数。

以下栏目不显示子抽屉：

- 获奖查询：直接跳转用户系统的证书查询入口；未登录时先显示用户登录。
- 联系我们：直接进入当前赛事的联系页面。
- 用户登录：直接进入用户系统登录页。
- 报名入口：直接进入赛事中心；未登录时先显示用户登录。

## 3. 桌面端交互

- 每个有子项的一级栏目拥有独立按钮和独立子抽屉。
- 鼠标悬停栏目时，在对应栏目正下方打开紧凑抽屉；鼠标移入抽屉后保持展开。
- 点击栏目可固定展开，再次点击关闭。
- 打开另一个栏目时，前一个抽屉自动关闭。
- 点击抽屉链接、页面空白区域或按 `Escape` 时关闭。
- 键盘可用 `Tab` 聚焦栏目，使用 `Enter` 或空格展开；展开后焦点进入首个子项，关闭后焦点返回触发按钮。
- 当前一级栏目和当前子页面均显示清晰的激活状态。
- 抽屉宽度由内容决定，但不得超出页面内容区或屏幕边缘。

原有全宽大抽屉、赛事主题卡片和抽屉内重复的一级导航全部移除。

## 4. 手机与窄屏交互

- 保留一个汉堡菜单按钮打开移动端菜单。
- 菜单使用纵向分组手风琴：点击“首页”“关于大赛”“赛事资讯”分别展开自己的子项。
- 同一时间只展开一个分组。
- 获奖查询和联系我们为直接链接。
- 用户登录和报名入口放在菜单底部的独立操作区，报名入口使用主按钮样式。
- 手机菜单打开时锁定页面背景滚动，关闭后恢复。
- 菜单内容可以纵向滚动，不产生横向裁切。

## 5. 视觉设计

### 5.1 头部布局

- 继续采用蓝白主色，与官网主体保持一致。
- Logo、一级导航和页面主体共享同一最大内容宽度，缩放时保持左右边界对齐。
- Logo 与平台名称保持稳定宽度；中间导航使用均衡间距，不挤压右侧操作区。
- 用户登录使用白色或浅色次按钮；报名入口使用高对比实心主按钮。
- 导航文字、按钮高度、圆角、边框和焦点状态使用统一设计变量。

### 5.2 子抽屉

- 使用白色背景、细边框、轻阴影和适度圆角。
- 抽屉紧贴对应触发栏目下方，使用短距离淡入与位移动画。
- 子项采用单列布局，保证名称清晰；悬停和键盘焦点状态使用品牌蓝色。
- 减少动画设置生效时取消过渡，内容立即显示或隐藏。

### 5.3 整体页面协调

- 统一头部与首屏之间的间距，避免导航压迫正文或出现过大空白。
- 在 1440、1024、768、390 像素宽度下检查内容区、头部和卡片边缘对齐。
- 本次只调整共用官网头部及其对页面首屏的影响，不重做各业务页面主体。

## 6. 前后台名称统一

### 6.1 前台

以下位置统一使用新名称：

- 首页栏目标题；
- 导航与子抽屉；
- 通知公告、新闻动态、赛事回顾列表页标题；
- 赛事详情的内容分类标签；
- 页面标题、SEO 标题、空状态和说明文字中对内容类别的称呼。

### 6.2 后台

以下位置统一显示：`通知公告`、`新闻动态`、`赛事回顾`：

- 内容列表的类型筛选和类型徽标；
- 新建、编辑和转载导入的类型选择；
- 发布检查和预览中的类型名称；
- 空状态及操作提示。

后台只修改显示标签，不修改接口字段、数据库枚举或历史数据。

## 7. 状态与降级

- 当前赛事数据加载失败时，导航仍可使用不依赖赛事的基础链接。
- 没有当前赛事时，公开页面链接不附加 `event` 参数。
- 登录与报名入口始终保持可见，不依赖抽屉加载状态。
- JavaScript 动画状态不得导致链接在关闭后仍可被键盘聚焦。

## 8. 测试与验收

### 8.1 自动化测试

- 导航配置测试：校验三个分组及其准确链接，直达项不得拥有子项。
- 组件测试：分别验证悬停、点击、互斥展开、空白关闭、`Escape`、焦点恢复和路由切换关闭。
- 移动端测试：验证手风琴结构、登录报名操作区、滚动锁定和直达链接。
- 名称测试：前后台不得再把 `announcement` 显示为“赛事公告”或普通“公告”，不得把 `news` 显示为“赛事动态”或普通“新闻”。
- 回归测试：公开路由、赛事参数、登录、报名和证书入口保持原有行为。

### 8.2 浏览器验收

- 1440 像素桌面：三个抽屉分别在对应栏目下展开，右侧按钮整齐，无全宽大抽屉。
- 1024 与 768 像素：布局在断点处稳定切换，无导航挤压。
- 390 像素手机：分组可独立展开，操作按钮清晰，无横向滚动。
- 仅用键盘完成展开、进入链接、关闭和焦点恢复。
- 线上检查前台导航、内容列表和后台内容管理的新名称一致。

## 9. 非目标

- 不改变内容数据库结构和 API 类型值。
- 不新增内容栏目或迁移历史文章。
- 不修改用户权限、报名流程和证书业务逻辑。
- 不重做官网所有页面的主体版式。
