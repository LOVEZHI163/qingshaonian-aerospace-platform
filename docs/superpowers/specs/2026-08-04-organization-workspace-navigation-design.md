# 组织用户工作台导航与报名记录改版设计

日期：2026-08-04

## 目标

统一组织用户的新旧导航，重新划分赛事报名、报名记录、组织管理和证书查询的职责，并改善组织报名表的输入约束和页面层级。改版后，组织管理员应能稳定地从侧边栏进入各项功能，查看本组织跨赛事的全部历史报名，同时不能看到其他组织的数据。

## 范围

本次包含：

- 固定组织用户侧边栏菜单；
- 合并资质审核进度与组织成员管理入口；
- 简化单场赛事工作台，只保留赛事信息和新增组织报名；
- 新增组织级、跨赛事的报名记录页面；
- 将成绩和奖项合并到报名记录；
- 将年级改为规范下拉；
- 新建组织报名时默认使用当前组织名称作为学校，并允许修改；
- 优化组织报名页的卡片、表单和移动端布局；
- 补充明确的中文异常信息和自动化测试。

本次不改变赛事发布规则、证书发布流程、成员邀请规则、作品文件规格或平台管理员权限。

## 导航与页面职责

组织用户登录后的侧边栏始终按以下顺序显示：

1. 赛事工作台
2. 报名记录
3. 组织与成员
4. 证书查询
5. 退出登录

侧边栏不再根据组织审核状态替换菜单名称，也不再出现独立的“审核进度”。

### 赛事工作台

赛事工作台的第一层展示组织当前可参与的全部赛事。点击赛事卡片时：

- 尚未加入且组织资质有效：先加入赛事，再进入赛事报名页；
- 已加入：直接进入赛事报名页；
- 资质无效或赛事不可访问：禁止进入，并显示明确原因。

单场赛事报名页不再显示“组织报名、报名记录、成绩、证书”横向导航，只包含：

- 返回赛事工作台；
- 赛事信息摘要；
- 报名说明；
- 组织报名表；
- 作品类赛项所需的图片和视频上传区。

### 报名记录

报名记录是组织级、跨赛事页面，不依赖当前赛事上下文。页面支持：

- 按赛事筛选；
- 按姓名、手机号或报名编号搜索；
- 按赛项筛选；
- 按审核状态筛选；
- 服务端分页；
- 展示赛事名称、报名编号、姓名、学校、年级、赛项、作品材料、指导老师、审核状态、成绩、奖项和操作；
- 从记录进入对应赛事上下文进行允许的修改或作品材料替换。

原独立“成绩”标签取消，成绩、名次和奖项统一显示在报名记录中。

### 组织与成员

“组织与成员”始终存在：

- 组织尚未通过审核时，显示审核状态、驳回原因和重新提交资质入口；
- 组织审核通过后，显示成员加入申请、组织邀请、正式成员和历史关系。

### 证书查询

证书查询继续作为独立的跨赛事入口，只显示当前组织可访问的已发布证书，并保留筛选、预览和下载能力。

## 报名表设计

赛事报名页由三个卡片组成：

1. 赛事信息卡：赛事名称、比赛时间、地点、报名截止时间、报名状态和返回入口。
2. 报名说明卡：明确报名自动归属当前组织，学校可修改。
3. 报名信息卡：姓名、学校、年级、手机号、赛项和指导老师；宽屏两列，窄屏单列。

### 年级下拉

年级不再允许自由输入，固定选项为：

- 一年级、二年级、三年级、四年级、五年级、六年级；
- 初一、初二、初三；
- 高一、高二、高三；
- 职高一年级、职高二年级、职高三年级。

本次只约束输入值，不增加年级与赛项的前端联动筛选。服务端继续根据规范年级推导组别并执行赛项适用组别校验。

### 学校默认值

- 新建报名时，学校默认填写当前组织名称；
- 组织管理员可以修改学校；
- 成功提交一条报名并重置表单后，学校恢复为当前组织名称；
- 编辑已有报名时保留该记录原来的学校，不以组织名称覆盖；
- 组织资料暂时加载失败时，学校保持可手工输入，不阻断报名。

## 数据边界与历史归属

组织级报名记录接口只返回报名记录中 `organizationId` 等于当前组织 ID 的数据。该条件覆盖：

- 当前组织直接提交的组织代报名；
- 组织正式成员以个人身份提交、但明确归属于当前组织的报名；
- 成员退出组织后，在其加入期间已经归属于该组织的历史报名。

历史归属以报名创建或合并时保存的 `organizationId` 为准，不根据成员当前状态临时推断。以下数据必须排除：

- `organizationId` 属于其他组织的报名；
- 没有归属当前组织的个人报名；
- 仅因当前手机号、姓名或当前成员关系相似而匹配出的报名。

API 必须从登录会话和组织负责人关系推导当前组织，客户端不得提交任意组织 ID 扩大查询范围。

## 数据流与接口

1. 组织用户登录后恢复会话及其唯一负责组织。
2. 侧边栏固定渲染，不以审核状态改变菜单集合。
3. 赛事工作台通过账户赛事接口获取可参与赛事，并在需要时调用加入赛事接口。
4. 单场赛事报名页加载赛事工作台数据，其中包含赛事、赛项、组织摘要和当前组织名称。
5. 报名表使用服务端提供的组织名称初始化学校，使用固定年级枚举提交报名。
6. 跨赛事报名记录页面调用组织级分页接口。服务端从会话确定组织 ID，再以报名记录的 `organizationId` 做强制过滤，并应用可选筛选条件。
7. 编辑或替换材料时，使用记录自身的赛事 ID 跳转到对应赛事范围接口，服务端再次校验组织归属。

组织级报名记录响应统一包含 `rows`、分页元数据以及筛选所需的赛事和赛项选项，页面不再额外拼接其他赛事上下文接口。实现时复用现有组织报名序列化和赛事权限校验，避免形成第二套字段定义。

## 异常与空状态

- 赛事不存在：提示“赛事不存在或已不可访问”，提供返回赛事工作台入口。
- 组织未加入赛事：提示加入赛事后再报名；允许加入时提供加入按钮。
- 组织尚未通过资质审核：赛事工作台展示不可操作状态，“组织与成员”页面提供审核进度。
- 年级非法：前端下拉避免自由输入；服务端仍返回明确的字段错误。
- 报名记录为空：显示“当前组织暂无报名记录”，不误报加载失败。
- 接口或网络失败：显示简洁中文信息和“重新加载”，不得把 HTML 错误页源码直接渲染给用户。
- 越权记录请求：返回 403 或 404，前端显示无访问权限，不泄露其他组织信息。

## 测试与验收

### 管理端测试

- 待审核和已审核组织均显示同一套侧边栏菜单；
- “审核进度”不再出现；
- 赛事报名页不再出现四项横向导航；
- 年级为下拉且包含全部十五个规范选项；
- 新建报名默认学校为组织名称，允许修改，提交重置后恢复默认；
- 编辑报名保留原学校和年级；
- 报名记录跨赛事展示并支持筛选、分页；
- 成绩和奖项显示在报名记录中；
- 桌面与窄屏布局无横向溢出。

### API 测试

- 组织级查询只返回 `organizationId` 为当前组织的数据；
- 当前成员归属于组织的个人报名可见；
- 已退出成员的历史归属报名仍可见；
- 无组织归属和其他组织的报名不可见；
- 伪造组织 ID 不能扩大查询范围；
- 筛选、分页和空结果稳定；
- 修改报名和替换作品材料继续执行赛事与组织双重权限校验。

### 发布验收

- 完整 API、管理端和官网测试通过；
- 生产构建与配置检查通过；
- 部署前备份数据库、上传卷和可回滚镜像；
- ECS 更新后所有容器健康；
- 使用组织测试账号验证固定侧边栏、赛事报名、跨赛事记录、组织审核页面和证书查询；
- 验证其他组织数据不会出现在响应或页面中；
- 验证普通赛事与图片/视频作品赛事的报名均可完成。
