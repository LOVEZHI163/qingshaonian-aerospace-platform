# 公开前端隐藏“优秀作品”设计

## 目标

从公开网站彻底移除“优秀作品”的展示和访问入口，同时保留后台内容类型、历史内容和数据库数据，确保未来可以恢复。

## 公开端行为

- 首页不展示“优秀作品”模块；维持现有已隐藏状态并增加回归保护。
- `/news` 仅展示“新闻动态”，页面标题、说明、SEO 文案不再出现“优秀作品”。
- `/news` 不再渲染内容分类标签栏，只请求并展示 `news` 类型内容。
- 访问旧链接 `/news?type=work`、重复或非法的 `type` 参数时，统一按“新闻动态”处理；保留合法的 `event` 筛选与页码语义，不请求 `work` 内容。
- 访问类型为 `work` 的公开内容详情时，展示现有“内容不存在”页面，不渲染正文、附件或媒体。
- 公开首页 SEO 默认说明及内容详情兜底说明不再提及“优秀作品”。

## 后台与数据边界

- 管理后台继续保留“优秀作品”类型、筛选、编辑和历史记录。
- API 数据模型、数据库枚举和既有记录不删除、不迁移。
- 本次不改变管理员发布流程，也不批量撤销已发布状态。

## 实现边界

- 列表页只维护单一 `news` 数据流，删除公开端作品标签切换逻辑。
- 详情页在拿到公开内容后检查 `row.type`；若为 `work`，使用与 404 相同的公开降级界面。
- 路由查询解析将公开资讯类型收敛为 `news`，旧 `work` 参数不会传播到翻页或筛选链接。
- 公开类型标签映射可以继续保留 `work`，供内部兼容或详情数据识别使用，但不得产生公开入口。

## 验收标准

1. 首页和 `/news` 页面均找不到“优秀作品”文字或入口。
2. `/news` 只发起 `type=news` 请求。
3. `/news?type=work&event=E1` 展示 E1 的新闻动态，不请求作品数据。
4. 已发布 `work` 内容的详情 URL 显示“内容不存在”。
5. 管理后台仍能看到并管理“优秀作品”类型。
6. 公开前端全量测试、构建和桌面/移动浏览器验收通过后再部署。
