# 官网正文 B 站视频组件设计

日期：2026-08-05  
状态：书面设计已批准

## 1. 背景与目标

赛事管理平台的“官网内容 → 内容发布 → 正文与媒体”目前支持文字、链接和站内图片，但不支持在正文中播放外部视频。管理员需要能在正文任意位置插入哔哩哔哩视频，并在官网中通过视频封面直接原位播放。

本功能只支持哔哩哔哩普通投稿视频，不扩展到其他视频网站或哔哩哔哩直播。

目标：

- 管理员只需填写完整 B 站视频链接或 BV 号，以及自定义视频标题。
- 正文中以可编辑的视频组件保存，而不是接受管理员粘贴的任意 `iframe`。
- 官网显示 B 站播放器自带封面，访客点击封面后在当前位置播放。
- 不在本服务器下载或保存视频、封面，不增加媒体存储占用。
- 保持现有正文脚本和任意 `iframe` 过滤规则。

## 2. 第一版范围

支持输入：

- `https://www.bilibili.com/video/BV...`、`https://m.bilibili.com/video/BV...` 或不带 `www` 的同类完整视频链接，可带 B 站自身的普通查询参数。
- 直接输入符合 `^BV[0-9A-Za-z]{10}$` 的 BV 号。

不支持：

- `b23.tv` 短链接。解析短链接需要额外的服务器网络跳转处理，与本期“后端保持简单”的目标冲突。
- AV 号、番剧、直播、播放列表和其他视频网站。
- 自动读取视频标题；标题由管理员填写。
- 下载 B 站封面或视频到本服务器。
- 自动播放。

## 3. 管理后台交互

### 3.1 工具栏入口

在正文可视化编辑器的“图片”按钮右侧增加“B站视频”按钮。

- 按钮文字固定为“B站视频”，避免与站内上传视频或参赛作品视频混淆。
- 鼠标悬停提示：“粘贴B站完整链接或BV号，插入可播放视频”。
- 按钮旁提供帮助提示，明确列出支持的两种输入形式，并说明暂不支持 `b23.tv` 短链接。

### 3.2 插入弹窗

弹窗包含：

- “视频链接或 BV 号”：必填。
- “视频标题”：必填，由管理员自行设置。
- 识别结果：校验成功后显示识别出的 BV 号和 16:9 播放器预览。
- “插入正文”按钮：仅在链接和标题均合法时启用。

弹窗顶部显示操作说明：“填写B站完整视频链接或BV号和自定义标题，系统将生成封面与播放器。”

输入错误时使用明确提示：

- 未找到 BV 号：“未识别到有效BV号，请粘贴完整B站视频链接或直接输入BV号。”
- 输入短链接：“暂不支持b23.tv短链接，请打开短链接后复制浏览器中的完整视频地址。”
- 标题为空：“请填写视频标题。”

### 3.3 正文内编辑

- 新视频插入当前光标位置。
- 视频组件在可视化编辑器中显示 16:9 预览、标题和“在哔哩哔哩打开”链接。
- 点击已插入组件可修改标题、更换视频链接或删除组件。
- 一篇内容可插入多个 B 站视频。
- 保存草稿、重新打开、发布、撤回和再次发布均不得丢失组件。

## 4. 数据表示与组件边界

正文中保存受控的语义标记，不直接保存播放器 `iframe`。建议规范形式：

```html
<figure class="content-bilibili-video" data-bilibili-video="BVxxxxxxxxxx">
  <figcaption>管理员设置的视频标题</figcaption>
</figure>
```

该标记只包含：

- 经过格式校验的 BV 号。
- 经过 HTML 转义的标题文本。

不新增数据库表或字段，继续使用现有正文 HTML 存储。职责拆分如下：

- 管理端 B 站视频扩展：负责插入、选择、修改和删除正文视频节点。
- 管理端视频弹窗：负责输入提示、BV 号提取和预览。
- API 正文清洗：仅允许规范的视频占位标记及其安全属性，继续移除所有任意 `iframe`、脚本和非法属性。
- 官网视频组件：只从合法 BV 号构造固定的 B 站播放器地址并负责响应式展示。

## 5. 官网播放行为

官网将安全占位标记渲染为固定来源的播放器：

`https://player.bilibili.com/player.html?bvid=<BV号>&poster=1&autoplay=0&danmaku=0`

展示规则：

- 播放区域保持 16:9，宽度不超过正文容器。
- 使用浏览器原生懒加载；进入临近可视区域时加载播放器和 B 站封面，不预先下载视频文件。
- 默认显示 B 站播放器封面，访客点击封面后在当前位置播放。
- 默认不自动播放、默认关闭弹幕并允许全屏。
- 播放器下方显示管理员设置的标题和始终可用的“在哔哩哔哩打开”链接。
- 草稿预览、已保存内容预览和正式官网共用同一渲染组件。

由于播放器是跨域页面，本站无法可靠判断视频是否已被删除或禁止外链。因此不伪造“加载失败”状态；始终保留外部观看链接作为退路。

## 6. 编辑模式兼容

- 可视化模式：完整插入和编辑 B 站视频组件。
- HTML 模式：显示规范占位标记；手工加入的任意 `iframe` 保存时仍被移除。
- 纯文本模式：无法保留图片或视频等结构化媒体。正文含媒体时，切换前显示确认提示：“纯文本编辑会移除正文媒体，是否继续？”只有管理员确认后才切换。

## 7. 安全约束

- BV 号只允许符合 `^BV[0-9A-Za-z]{10}$` 的 ASCII 字母和数字，不允许拼接额外查询参数或 HTML。
- 官网播放器地址由应用固定生成，管理员不能控制域名、协议或播放器参数。
- API 不访问管理员提供的网址，不执行短链接跳转，不调用 B 站数据接口。
- API 继续删除 `script`、`style`、任意 `iframe`、事件属性和危险 URL 协议。
- 网站内容安全策略只为 `https://player.bilibili.com` 增加必要的 `frame-src` 权限。
- 视频标题按普通文本处理，不允许包含可执行 HTML。

## 8. 测试与验收

自动测试至少覆盖：

- 从完整 B 站链接和直接 BV 号提取同一 BV 号。
- 拒绝 `b23.tv`、其他域名、AV 号、缺失 BV 号和包含恶意 HTML 的输入。
- 插入、修改标题、更换链接、删除以及同一正文多个视频。
- 可视化和 HTML 模式往返后视频节点不丢失。
- 正文含媒体时切换纯文本模式出现确认提示。
- 服务端清洗保留合法占位标记并删除伪造属性、任意 `iframe` 和脚本。
- 草稿预览和公开内容使用相同播放器地址、标题及外部观看链接。
- 电脑、平板和手机宽度下保持 16:9，页面无横向滚动。
- 保存草稿、重新加载、发布、撤回和重新发布后的内容一致。

上线验收标准：

1. 管理员能在“正文与媒体”中看见带操作提示的“B站视频”按钮。
2. 粘贴完整链接或 BV 号并填写标题后，可在光标位置插入视频。
3. 官网访客看见 B 站封面，点击后直接原位播放。
4. 视频不占用本站媒体存储，服务器不请求 B 站解析接口。
5. 非 B 站播放器和恶意 HTML 无法通过保存或发布进入官网。
