# 赛事设置导航整合设计

日期：2026-07-18  
状态：已确认

## 背景

管理员侧栏当前同时提供“赛事管理”和“赛项与组别”两个入口。两个入口只改变侧栏高亮和 `currentView`，但都渲染同一个 `EventManagementPage`。页面不会根据入口切换内容或滚动位置，因此点击“赛项与组别”后仍停留在赛事信息顶部，造成导航失效的观感。

赛事基本信息、报名开放状态、赛项和适用组别都依赖同一届赛事。它们属于同一个管理上下文，应合并为一个侧栏模块。

## 目标

- 侧栏只保留一个“赛事设置”入口。
- 赛事设置页面提供“赛事信息”和“赛项与组别”两个内部标签。
- 点击内部标签时真正切换可见内容，而不只是改变高亮。
- 切换标签时保留当前选中的赛事、已加载数据和表单状态。
- 不修改数据库结构、API 或现有赛事与赛项业务规则。
- 原页面全部业务功能必须保留，本次不做功能删减。

## 必须保留的功能

“赛事信息”标签完整保留：

- 多届赛事列表与赛事选择
- 新建赛事草稿、编辑和保存赛事
- 比赛日期、地点、联系方式和报名起止时间
- 报名状态自动控制、临时开放和临时关闭
- 复制赛事、设为当前赛事和归档赛事
- 历史赛事附件清理与危险删除保护

“赛项与组别”标签完整保留：

- 当前赛事的赛项列表
- 新增和编辑赛项
- 个人赛/团体赛、类别和显示顺序
- 启用状态与“必须填写指导老师”设置
- 小学低段、小学高段、中学组、职高/高中组设置
- 有报名历史时停用、无报名历史时删除的保护规则

## 方案

### 侧栏导航

删除独立的 `projects` 导航项，将原 `events` 导航显示名称改为“赛事设置”。管理员侧栏模块数量由七个变为六个。

`App.vue` 只使用 `events` 作为赛事设置视图键，不再把 `projects` 映射到同一页面。概览中的赛事跳转继续进入 `events`。

### 页面内部标签

`EventManagementPage` 新增页面级标签状态，默认显示“赛事信息”：

- “赛事信息”：显示赛事列表、赛事编辑表单、报名时间、临时开放/关闭、复制、设为当前和归档操作。
- “赛项与组别”：显示当前赛事名称、赛项列表、赛项编辑/新增表单及四个适用组别。

两个标签共享同一个赛事选择状态。切换到“赛项与组别”时，如果已有选中赛事，直接展示该赛事的赛项；没有赛事时显示“请先创建或选择赛事”的空状态。

为避免切换标签后无法更换赛事，“赛项与组别”标签中保留一个赛事选择控件。改变赛事时复用现有 `selectEvent` 逻辑，并清空尚未保存的赛项编辑状态。

### 状态与数据流

1. 进入“赛事设置”后加载赛事、赛项和报名历史。
2. 默认选择当前赛事，并显示“赛事信息”。
3. 管理员切换内部标签只改变本地展示状态，不重新请求数据。
4. 管理员在任一标签切换赛事时，赛事信息与赛项列表同步指向同一个 `selectedId`。
5. 保存赛事或赛项后继续使用现有重新加载逻辑，并保留所选赛事和当前标签。

### 错误与安全行为

- 加载、保存和冲突错误继续使用现有页面消息区域。
- 切换标签本身不触发写操作，不丢失已保存数据。
- 赛项已有报名时继续只允许停用，不允许物理删除。
- 归档、资源清理和危险删除规则保持不变。

## 测试设计

测试先于实现，并覆盖以下行为：

1. 管理员侧栏只显示“赛事设置”，不再显示独立“赛项与组别”。
2. 点击“赛事设置”只进入一个赛事视图键。
3. 页面默认只显示赛事信息区域。
4. 点击“赛项与组别”标签后隐藏赛事编辑区域并显示赛项区域。
5. 内部标签切换不会重新调用加载接口，并保留已选择赛事。
6. 在赛项标签切换赛事后，赛项列表与表单指向新赛事。
7. 既有赛事、赛项、报名历史保护和资源清理测试继续通过。
8. 部署后在真实管理页面验证侧栏单入口和两个内部标签切换。

## 验收标准

- 侧栏只有一个“赛事设置”入口。
- 点击入口后默认看到赛事信息。
- 点击“赛项与组别”内部标签后，首屏直接显示当前赛事的赛项，不需要手工滚动。
- 再切回“赛事信息”时仍保持原赛事选择。
- 原有赛事和赛项管理功能、权限及数据均不受影响。
- 上述“必须保留的功能”逐项可用，不因标签切换而丢失表单或赛事选择状态。

## 非目标

- 不拆分或新增后端接口。
- 不改变赛事、赛项、组别的数据模型。
- 不引入 URL 路由或浏览器历史记录。
- 不改动普通用户和组织用户导航。
