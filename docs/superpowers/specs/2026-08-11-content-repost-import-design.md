# 官网内容快速转载设计

## 1. 目标与范围

平台管理员需要在“官网内容 → 内容发布”中快速转载两类公开内容：

1. 微信公众号文章；
2. 其他公开新闻网页。

管理员粘贴原文链接后，系统在服务器端提取标题、作者、发布时间、摘要、正文和正文图片，经过安全清理与人工预览后保存为未发布草稿。管理员仍须通过现有内容编辑与发布流程检查、修改和发布。

本功能不提供浏览器扩展、不接入第三方付费解析服务、不在抓取失败后提供复制粘贴式降级导入，也不直接发布转载内容。导入网页中的视频和外部播放器不予保留；B 站视频继续通过系统已有的“插入 B 站视频”能力单独添加。

## 2. 已确认的产品原则

- 采用服务器抓取、解析并创建草稿的方案。
- 微信公众号使用专用解析规则，其他网页使用通用正文抽取规则。
- 原作者、来源网站或公众号、原文链接为必填来源信息。
- 正文图片下载到本系统服务器，不继续引用第三方图片地址。
- 自动过滤头像、二维码区域、广告、跟踪图和尺寸过小的图片；管理员在预览阶段可继续删除图片。
- 同一标准化原文链接只能导入一次；发现重复时阻止新建并提供“打开已有内容”。
- 抓取或正文解析失败时不创建草稿，只返回明确的中文错误提示。
- 所有成功导入的内容默认保存为 `draft`，不能由导入接口直接发布。

## 3. 管理员操作流程

### 3.1 入口

“官网内容 → 内容发布”的内容列表顶部保留“新建内容”，并增加并列主操作“转载内容”。

点击“转载内容”后进入三步流程：

1. 粘贴链接；
2. 检查预览；
3. 保存草稿。

### 3.2 粘贴链接

管理员输入公开的 HTTP 或 HTTPS 链接并点击“开始提取”。页面提示：

- 支持微信公众号和公开新闻网页；
- 重复链接会打开已有内容；
- 导入结果只保存为草稿。

提交期间显示“正在验证链接”“正在提取正文”“正在下载图片”三个可理解的阶段状态，不允许重复提交。

### 3.3 检查预览

预览页分成正文与图片两个区域。

正文区域展示并允许修改：

- 标题；
- 摘要；
- 归属赛事与内容类型；
- 清理后的正文；
- 原作者；
- 来源网站或公众号；
- 原文发布时间；
- 原文链接。

标题、摘要和正文沿用现有内容编辑能力。来源网站或公众号名称、原作者允许修正但不可清空；原文链接和规范链接在本批次中只读，避免来源内容与去重指纹不一致。若链接本身有误，管理员应取消本批次并用正确链接重新提取。

图片区展示已成功下载的候选图片、被选为封面的图片和失败图片。管理员可以：

- 更换封面候选；
- 删除无关图片；
- 对失败图片重试；
- 查看过滤数量和过滤原因摘要。

失败图片必须被成功重试或由管理员删除后，才能保存草稿。

### 3.4 保存草稿

点击“保存为草稿”后，系统把临时图片转入正式内容媒体目录，创建内容记录并打开现有内容编辑页。保存完成后显示来源信息，管理员可继续编辑、预览和走现有发布检查流程。

管理员取消、关闭或批次过期时，不创建内容记录，临时文件由系统清理。

## 4. 内容与来源数据

内容记录增加或扩展以下来源字段：

- `sourceType`：`wechat` 或 `web`；
- `sourceUrl`：管理员提交的原始链接；
- `canonicalSourceUrl`：安全校验后的最终规范链接；
- `sourceUrlFingerprint`：规范链接的稳定摘要，用于防重复；
- `sourceName`：公众号名称或网站名称；
- `sourceAuthor`：原文作者；
- `sourcePublishedAt`：可选的原文发布时间；
- `importedAt`：导入时间；
- `importedByUserId`：执行导入的平台管理员。

`canonicalSourceUrl` 的生成规则包括：

- 主机名转为小写；
- 删除 URL 片段；
- 删除默认端口；
- 删除明确的跟踪参数，如 `utm_*`、`spm`、`from`；
- 优先采用页面中通过同等安全校验的 canonical 地址；
- 保留识别文章所必需的查询参数，避免错误合并不同文章。

数据库对有效的 `sourceUrlFingerprint` 建立唯一约束，不能只依靠前端检查。重复导入接口返回已有内容编号、标题和编辑地址。

公开内容页在正文末尾统一展示：原作者、来源、原文链接和“内容版权归原作者及原发布平台所有”的来源说明。

## 5. 导入批次与文件生命周期

抓取预览不直接创建内容。后端建立短期导入批次，记录：

- 批次编号；
- 管理员编号；
- 当前状态；
- 来源元数据；
- 清理后的正文候选；
- 图片候选及下载状态；
- 警告与错误；
- 创建时间和过期时间。

图片先写入受控的 `import-staging` 临时目录。文件名由系统生成，不采用远端文件名作为存储路径。批次只允许创建者本人和平台管理员会话访问。

提交草稿时使用现有串行变更锁或数据库事务：

1. 再次验证批次归属、有效期和重复链接；
2. 将临时图片写入正式内容媒体目录并创建媒体记录；
3. 重写正文中的图片引用为本系统媒体地址；
4. 创建 `draft` 内容记录；
5. 完成数据库提交；
6. 清理临时批次。

正式文件写入后数据库提交失败时，删除本次新文件；删除失败则写入现有文件清理日志或孤立文件日志。数据库提交成功后发生临时目录清理失败，不回滚已创建草稿，而是记录可重试清理任务。

批次默认 30 分钟过期。系统定时清理过期批次，并每天检查导入暂存区中的孤立文件。

## 6. 网页抓取与 SSRF 防护

抓取接口仅允许平台管理员调用。浏览器只提交 URL，所有远程请求由 API 服务执行。

### 6.1 URL 规则

- 只允许 `http:` 和 `https:`；
- 拒绝带用户名或密码的 URL；
- 默认只允许 80 和 443 端口；
- 拒绝本机名、单标签主机名和明显的内部域名；
- 拒绝环回、私网、链路本地、运营商级 NAT、组播、保留地址、IPv6 ULA、IPv4 映射私网地址和云服务元数据地址。

### 6.2 DNS 与跳转

首次请求和每次跳转前都重新执行安全检查。DNS 返回的全部 A 和 AAAA 地址必须属于公网；只要包含受限地址就拒绝请求。

实际连接须固定到已经检查过的解析地址，同时保留正确的 Host 与 TLS SNI，避免校验后再次解析造成 DNS rebinding。最多允许 3 次跳转，每个跳转目标都重复完整校验。

### 6.3 资源限制

- 单次 HTML 请求超时 10 秒；
- HTML 响应体最大 5MB，并限制解压后的累计读取量；
- 只接受可识别的 HTML 内容类型；
- 单个管理员每分钟最多发起 10 次提取；
- 每次导入最多保留 20 张图片；
- 单张远程图片最大 5MB；
- 单次导入图片总量最大 50MB。

磁盘使用达到 80% 时显示警告；达到 90% 时停止新的转载图片下载，返回稳定错误码并引导管理员进入存储管理。

## 7. 正文解析与清理

### 7.1 微信公众号

微信公众号解析器优先读取微信文章的标题、公众号名称、作者、发布时间和正文容器，并使用微信图片真实地址属性。它明确排除：

- 公众号头像和账号信息卡；
- PC 二维码和关注二维码区域；
- 赞赏、在看、分享和推荐模块；
- 页头、页脚及交互工具；
- 广告、跟踪图和非正文资源。

### 7.2 普通新闻网页

通用解析器组合使用 Open Graph、Schema.org/JSON-LD、常见 meta 字段和正文可读性算法。正文只从主要文章区域提取，忽略导航、侧栏、页脚、推荐阅读、评论和广告区域。

无法可靠识别标题或正文时返回“未识别到有效文章正文”，不创建空草稿。

### 7.3 HTML 清理

清理逻辑复用并扩展现有内容 sanitizer，只保留平台正文需要的安全结构，例如段落、H2/H3、列表、引用、强调、普通链接和本地化后的图片。

必须移除：

- `script`、`style`、`form`、`iframe`、`video`、`audio`、`object`、`embed`；
- 所有内联事件处理器；
- 危险协议和远程跟踪属性；
- 未经许可的 class、id、style 和 data 属性；
- 外部播放器、互动组件和第三方表单。

导入内容中的 B 站 iframe 也会被移除。管理员需要视频时，在保存草稿后使用已有的 B 站视频按钮重新插入。

## 8. 图片处理

只接收经文件签名验证的 JPG、PNG 和 WebP。远端声明的扩展名或 Content-Type 不能代替真实文件检测。

图片通过现有图片处理链路解码、去除元数据并生成站内媒体文件。图片请求设置合理的来源页 Referer 和固定 User-Agent，但不携带管理员 Cookie、服务器凭据或用户请求头。

自动过滤使用可解释的规则：

- 位于已识别广告、二维码、页头、页脚、账号卡或推荐模块中；
- 微信已知二维码和头像节点；
- 透明跟踪像素或尺寸过小；
- 重复图片；
- 无法解码或不受支持的格式。

系统不承诺通过图像识别发现所有二维码或广告，因此预览页必须提供人工删除能力。第一张合格正文图片默认成为封面候选，管理员可以更换或取消。

## 9. 后端接口

建议新增以下管理员接口，最终路径可按项目现有路由约定调整：

- `POST /api/admin/site-content-imports/preview`：校验 URL、抓取、解析和暂存图片；
- `GET /api/admin/site-content-imports/:batchId`：读取本人批次及当前状态；
- `POST /api/admin/site-content-imports/:batchId/images/:imageId/retry`：重试失败图片；
- `DELETE /api/admin/site-content-imports/:batchId/images/:imageId`：删除候选图片；
- `POST /api/admin/site-content-imports/:batchId/commit`：以管理员修订后的字段创建草稿；
- `DELETE /api/admin/site-content-imports/:batchId`：取消并清理批次。

预览接口先用提交链接的规范结果检查重复；直接命中时返回 `409` 和 `IMPORT_DUPLICATE_SOURCE`，响应中只包含安全的已有内容摘要及编辑目标，不启动新的远程抓取。若重复只能在跳转或读取页面 canonical 地址后识别，则在下载正文后、暂存图片前再次检查并终止批次。

其他稳定错误码包括：

- `IMPORT_URL_INVALID`；
- `IMPORT_URL_BLOCKED`；
- `IMPORT_FETCH_TIMEOUT`；
- `IMPORT_RESPONSE_TOO_LARGE`；
- `IMPORT_UNSUPPORTED_CONTENT`；
- `IMPORT_ARTICLE_NOT_FOUND`；
- `IMPORT_IMAGE_FAILED`；
- `IMPORT_BATCH_EXPIRED`；
- `IMPORT_STORAGE_CRITICAL`。

管理员端根据错误码展示固定中文说明，不解析后端自由文本决定页面逻辑，也不向用户展示底层网络栈、文件路径或 HTML 错误页。

## 10. 审计与隐私

审计日志记录：

- 管理员；
- 原始来源主机和规范链接摘要；
- 批次和内容编号；
- 抓取结果、图片数量和失败类型；
- 创建、取消、过期清理和重复阻止操作。

审计日志不保存远端完整 HTML、图片二进制、管理员 Cookie、请求凭据或内部文件路径。错误日志中的 URL 查询参数按现有敏感信息规则清理。

## 11. 测试与验收

### 11.1 API 测试

使用本地固定夹具和受控 HTTP/DNS 测试服务，不依赖真实微信公众号或第三方新闻站点。至少覆盖：

- 微信文章与普通新闻文章成功解析；
- 标题、作者、来源、发布时间、摘要、正文和图片映射；
- 重复规范链接被数据库唯一约束和接口共同阻止；
- 非管理员、普通用户和组织用户均不能调用；
- 环回、内网、IPv6 私网、元数据地址、危险端口和带凭据 URL 被拒绝；
- 每次跳转重新校验，DNS rebinding 无法绕过；
- 超时、超大 HTML、非 HTML 响应和跳转超限；
- 恶意脚本、表单、iframe、事件属性和危险协议被清除；
- 图片签名、单张上限、总量上限、数量上限、重复过滤和失败重试；
- 取消、过期、提交失败和文件清理失败时的数据与文件一致性；
- 磁盘 80% 警告和 90% 阻止规则；
- 导入接口只能创建草稿，不能直接发布。

### 11.2 管理员端测试

- 内容列表同时显示“新建内容”和“转载内容”；
- 三步流程及各加载阶段清晰可见；
- 重复链接提示并能打开已有内容；
- 失败图片可重试或删除，未处理前不能提交；
- 标题、摘要、正文、归属赛事、类型和封面可检查修改；
- 保存后进入现有内容编辑页且状态为草稿；
- 所有失败状态显示稳定中文提示，不显示原始 HTML 错误页。

### 11.3 官网测试

- 发布后的转载内容正常渲染清理后的正文和本地图片；
- 正文不包含远程脚本、表单、iframe 或外链图片；
- 页面展示原作者、来源、原文链接和版权来源说明；
- 原有 B 站视频内容和普通原创内容不受影响。

### 11.4 上线验收

上线前执行完整 API、管理员端和官网测试，完成生产构建，并在真实浏览器中验证：微信公众号转载、普通新闻转载、重复链接、失败链接、图片删除、保存草稿、编辑发布和官网来源展示。

部署时先备份数据库、上传目录和当前发布版本。上线后观察抓取错误率、临时目录增长、媒体磁盘占用和清理任务结果，不把临时目录或导入批次暴露为公开静态资源。

## 12. 非目标与后续扩展

本期不包含：

- 自动绕过微信公众号或其他网站的访问限制；
- 登录后页面、付费内容或需要 Cookie 的页面抓取；
- 第三方解析服务；
- 浏览器插件；
- 自动发布；
- 自动转载视频、音频、评论区或互动组件；
- 抓取失败后的人工 HTML 粘贴导入。

后续如确有需要，可在独立设计中增加来源白名单、转载授权记录、抓取队列和更精细的媒体配额，但不得削弱本设计的服务器网络安全边界。
