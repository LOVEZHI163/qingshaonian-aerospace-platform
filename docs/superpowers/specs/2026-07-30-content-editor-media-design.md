# 官网内容富文本与正文媒体完善设计

日期：2026-07-30
状态：已确认，待实施

## 1. 背景与问题

管理员后台“官网内容 → 内容发布”的正文编辑能力目前不完整：

- 正文“图片”按钮只允许手工输入 `/api/public/media/...` 地址，管理员无法直接上传或选择已有媒体。
- 后端没有管理员媒体列表接口，无法构建可用的媒体选择器。
- 正文中的图片没有纳入内容媒体引用校验和发布流程。图片即使写入正文，媒体仍可能保持草稿状态，公开页面会返回 404。
- 当前编辑器依赖已弃用的 `document.execCommand`。工具栏获得焦点后可能丢失正文选区，格式操作和图片插入位置不可靠。
- 窄屏或较低视口下，底部粘性操作栏会换成两行并遮挡正文媒体区域。

本设计将内容编辑器升级为稳定的文章编辑工作流，并补齐正文图片从上传、选择、编辑、保存、发布到引用保护的完整数据链路。

## 2. 目标

### 2.1 编辑能力

正文工具栏提供：

- 段落
- 二级标题
- 三级标题
- 粗体
- 斜体
- 有序列表
- 无序列表
- 引用
- 链接
- 撤销
- 重做
- 清除格式
- 正文图片

### 2.2 图片能力

- 一篇正文可插入多张图片。
- 图片可上传新文件，也可从已有媒体中选择。
- 图片插入当前光标位置。
- 图片支持替代文本、图片说明、替换和删除。
- 草稿编辑时可以查看受保护的图片预览。
- 发布后图片使用公开媒体地址。
- 正文图片在桌面和手机页面中自适应容器宽度，不产生横向滚动。

### 2.3 保存行为

- 继续使用手动“保存草稿”。
- 明确显示“有未保存修改 / 已保存 / 保存失败”等状态。
- 离开存在未保存修改的内容时继续弹出确认提示。
- 不增加自动保存，避免多个管理员或多个标签页间发生隐式覆盖。

## 3. 非目标

本轮不实现以下功能：

- 字体、字号、文字颜色和背景色。
- 任意文本对齐方式。
- 表格编辑。
- 视频、音频和第三方嵌入。
- 协同实时编辑。
- 正文数据从 HTML 迁移到新的数据库结构。
- 在已发布状态直接编辑内容；已发布内容仍需先下线。

## 4. 方案选择

采用 TipTap（基于 ProseMirror）替换当前自制 `contenteditable`。

未采用继续扩展 `document.execCommand` 的方案，因为该 API 已弃用，选区、撤销栈和跨浏览器行为难以可靠维护。未采用分块式编辑器，因为它需要改变正文存储格式并迁移已有内容，超出本轮范围。

TipTap 只负责编辑状态与交互。系统继续使用经过清理的 `bodyHtml` 作为 API 和数据库格式，因此现有内容无需迁移。

## 5. 管理端交互设计

### 5.1 编辑器

`RichTextEditor` 使用 TipTap `EditorContent` 渲染正文。工具栏按钮根据当前选区显示激活和禁用状态。切换内容记录或服务器返回新版本时，编辑器以 `revision` 为边界替换文档；同一版本内的父组件回写不会重建编辑器或破坏选区。

HTML 与纯文本模式继续保留，作为修复和排错入口：

- HTML 模式允许查看和修复原始 HTML，但对父组件输出时始终进行清理。
- 纯文本模式保留段落换行语义。
- 从 HTML 或纯文本返回可视化模式时不丢失已输入内容。

### 5.2 正文图片弹窗

点击“图片”后保存当前编辑器选区，并打开弹窗。弹窗包含两个页签：

1. **上传新图片**
   - 支持 PNG、JPEG、WebP。
   - 显示文件名、尺寸、上传进度和失败原因。
   - 上传成功后自动选中该媒体，但由管理员确认后才插入正文。

2. **选择已有媒体**
   - 显示未清理的图片媒体。
   - 显示缩略图、文件名、媒体 ID、尺寸和用途。
   - 支持按文件名或媒体 ID 搜索。
   - 默认按创建时间倒序展示最近 100 张图片。

确认插入前可填写：

- 替代文本：建议填写，空值允许保存。
- 图片说明：可选；非空时输出 `figcaption`。

确认后恢复先前选区并插入图片。若原选区已失效，则插入到正文末尾并提示管理员。

### 5.3 已插入图片

点击正文图片后显示图片操作浮层：

- 编辑替代文本和图片说明。
- 选择其他媒体进行替换。
- 删除图片节点。

删除正文图片只解除正文引用，不立即物理删除媒体。管理员可在媒体选择器中删除未被任何内容引用的媒体；仍被封面、附件、赛事视觉或正文引用的媒体返回明确的占用提示。

### 5.4 页面布局

- 正文工具栏在编辑器顶部粘性显示，但不覆盖正文。
- 页面底部操作栏在桌面宽度保持单行。
- 在窄屏下使用紧凑按钮和横向可滚动操作区，不再换成占据两行的大按钮区域。
- 编辑器最小高度随视口调整，手机端不出现固定 240px 导致的内容挤压。

## 6. 正文图片 HTML 格式

正文图片的持久化格式为：

```html
<figure>
  <img src="/api/public/media/MEDIA_ID" alt="替代文本">
  <figcaption>图片说明</figcaption>
</figure>
```

没有图片说明时可省略 `figcaption`。系统只接受本站 `/api/public/media/:id` 图片地址，不接受外部图片 URL、Data URL、JavaScript URL 或任意 HTML 属性。

TipTap 的正文图片节点保存 `mediaId`、`alt` 和 `caption`。编辑状态通过自定义 NodeView 使用 `/api/admin/site-media/:id/preview` 展示草稿图片；序列化为 HTML 时始终输出公开地址。载入旧正文时，从公开图片地址解析媒体 ID 并恢复为图片节点。

## 7. API 与服务设计

### 7.1 管理员媒体列表

新增：

```text
GET /api/admin/site-media?kind=image&limit=100&q=
```

要求：

- 仅平台管理员且密码状态正常时可访问。
- 只返回未清理媒体。
- `kind=image` 只返回 PNG、JPEG、WebP。
- `limit` 上限为 100。
- `q` 按原始文件名或媒体 ID 进行不区分大小写搜索。
- 返回创建时间倒序的媒体元数据和管理员预览 URL，不返回物理存储路径。

现有上传接口继续使用：

```text
POST /api/admin/site-media
purpose=content-body
file=<image>
```

### 7.2 正文媒体引用提取

服务层新增纯函数，从已经过服务器清理的正文 HTML 中提取 `/api/public/media/:id` 媒体 ID。正文创建、更新、预览和发布都使用同一提取逻辑。

保存草稿时：

- 每个正文媒体 ID 必须对应未清理的媒体资产。
- 媒体 MIME 类型必须是 PNG、JPEG 或 WebP。
- 不改变媒体公开状态。

发布内容时：

- 同时提升封面、附件和正文图片的 `visibility` 为 `public`。
- 发布事务完成后公开地址可立即访问。

删除媒体时：

- `mediaReference` 同时检查正文 HTML。
- 任意内容正文仍引用该媒体时返回 `409 MEDIA_IN_USE`，并提示“媒体仍被文章正文引用”。

删除内容或从正文移除图片后：

- 正文引用自然消失。
- 媒体不会自动物理删除，避免误删被其他用途复用的文件。

## 8. 清理与安全

浏览器端和服务器端继续双重清理 HTML：

- 允许标签：`p`、`h2`、`h3`、`ul`、`ol`、`li`、`strong`、`em`、`blockquote`、`a`、`figure`、`img`、`figcaption`、`br`。
- 链接仅允许 `http`、`https` 和 `mailto`。
- 图片仅允许本站公开媒体路径。
- 删除脚本、样式、事件属性、iframe、SVG、MathML 和未知标签。
- 服务端不信任客户端提供的媒体 ID、MIME 类型或预览 URL。

媒体列表接口不返回 `filePath`、`storedName` 或服务器目录。上传、预览和删除继续沿用现有文件签名验证、路径约束和清理日志机制。

## 9. 错误处理

- 上传类型或签名错误：保留正文和弹窗状态，显示可理解的文件错误。
- 媒体列表加载失败：允许重试，不关闭弹窗，不影响已编辑正文。
- 媒体已被清理或不存在：禁止插入并刷新列表。
- 保存时正文引用无效：API 返回 422 和稳定错误码，管理端定位到正文媒体区域。
- 发布时正文媒体无效：阻止发布，不改变内容和媒体状态。
- 并发版本冲突：沿用现有 409 处理，保留本地修改并要求刷新。
- 图片插入时选区失效：插入正文末尾并显示非阻断提示。

## 10. 测试策略

### 10.1 管理端单元与组件测试

- 工具栏完整、可访问且能反映当前选区。
- 粗体、斜体、标题、列表、引用、链接、撤销、重做和清除格式。
- 点击工具栏不丢失选区。
- 图片弹窗上传、列表搜索、选择和错误重试。
- 图片在保存的选区插入；失效选区回退到正文末尾。
- 替代文本、图片说明、替换和删除。
- HTML/纯文本模式与服务器版本切换。
- 恶意 HTML 和不安全图片地址被移除。
- 手动保存状态和离开提醒。
- 低高度、小屏幕下工具栏和操作栏不遮挡编辑区域。

### 10.2 API 与服务测试

- 管理员媒体列表的鉴权、过滤、搜索、上限和响应字段。
- 草稿正文媒体存在性与 MIME 校验。
- 发布时正文图片与其他媒体一起公开。
- 正文引用阻止媒体删除。
- 从正文移除引用后允许删除。
- 服务器清理拒绝外部图片、脚本和事件属性。
- 预览不会持久化草稿或改变媒体公开状态。

### 10.3 集成与浏览器验收

- 新建草稿，上传两张图片并分别插入不同光标位置。
- 从媒体库选择已有图片。
- 编辑图片说明、替换图片并删除其中一张。
- 保存后刷新，正文结构和图片位置保持。
- 发布后从官网公开页面确认图片 HTTP 200、尺寸自适应、无控制台错误。
- 360px、904px 和桌面宽度检查无横向溢出、操作栏不遮挡。

## 11. 发布与回滚

- 先完成数据库和上传卷备份。
- API 和管理端必须同时发布，避免新编辑器调用尚未存在的媒体列表接口。
- 发布后使用临时草稿和临时图片完成真实浏览器验收。
- 验收后删除临时内容和未引用媒体，恢复测试环境干净状态。
- 若发布失败，回滚 API、Web 镜像和源码；本设计不包含数据库结构迁移，因此无需数据库降级。
