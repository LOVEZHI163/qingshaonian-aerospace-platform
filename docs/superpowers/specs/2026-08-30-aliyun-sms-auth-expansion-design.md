# 阿里云短信认证扩展设计

日期：2026-08-30
状态：已完成分段设计确认，待书面规格审核

## 1. 背景与现状

平台已经具备密码登录、邮箱链接找回密码、管理员后台重置密码，以及按用途隔离的阿里云短信挑战基础设施。现有短信能力包括：

- 已注册账号的短信验证码登录；
- 短信验证码重置密码；
- 6 位验证码、摘要存储、过期、错误次数、限流和一次性消费；
- 独立的登录与重置密码模板配置；
- 默认关闭、配置不完整时失败关闭的功能开关；
- 可选的阿里云验证码人机验证。

生产环境当前未启用短信功能，因为服务器尚未配置正式 RAM AccessKey 和用途模板 Code。公开注册仍只依赖姓名、手机号和密码，没有验证手机号归属。

阿里云控制台当前已有：

- 可用签名：`温州市少航科创中心`；
- 通用验证码模板：`SMS_337755325`；
- 通用模板正文：`您的验证码为：${code}，请勿泄露于他人！`；
- 通用模板状态：审核通过、正常；
- 移动、联通、电信签名报备状态：已报备待验证。

通用模板保留用于控制台测试，不作为正式注册、登录或重置密码模板配置。

## 2. 目标

本次扩展需要：

1. 为个人参赛账号注册增加短信手机号验证；
2. 为组织负责人账号注册增加短信手机号验证；
3. 保留并正式启用普通用户、组织负责人和平台管理员的短信登录；
4. 保留并正式启用普通用户、组织负责人和平台管理员的短信重置密码；
5. 保留密码登录、邮箱链接找回密码和管理员后台重置密码；
6. 使用注册、登录、重置密码三个独立的阿里云验证码模板；
7. 使用最小权限 RAM 程序用户从 `server115` 调用阿里云 `SendSms`；
8. 防止验证码盗刷、用途混用、账号枚举、凭证篡改和账号状态绕过；
9. 允许各短信功能独立失败关闭，不影响其他认证方式。

## 3. 非目标

本次不包含：

- 管理员公开注册或管理员权限申请；
- 短信通知报名、审核、成绩、证书或赛事动态；
- 短信营销、群发或国际短信；
- 用短信登录替换用户已有密码；
- 强制启用阿里云验证码人机验证；
- 修改现有会话角色、组织审核或邮箱验证体系；
- 删除现有通用验证码模板。

## 4. 账号规则

### 4.1 公开注册

- 公开注册只允许个人账号和组织负责人账号。
- 两种注册都必须先验证注册手机号。
- 一个手机号只能创建一个平台账号，账号类型不改变这一唯一性规则。
- 注册成功后不自动建立登录会话，页面返回登录入口，保持现有行为。
- 管理员没有公开注册入口，任何公开请求都不能创建管理员账号。

### 4.2 短信登录

允许短信登录的账号：

- 状态为启用的普通用户；
- 状态为启用的管理员；
- 用户状态为启用，且所属组织已审核通过并处于启用状态的组织负责人。

待审核、已驳回或已停用组织的负责人不能短信登录。验证码确认时必须重新读取最新账号和组织状态，发送后被停用的账号不能继续登录。

短信登录不修改密码，也不清除 `mustChangePassword`。处于强制改密状态的账号短信登录成功后，仍只能进入修改密码流程。

### 4.3 短信重置密码

状态为启用的普通用户、组织负责人和管理员均可短信重置密码。待审核或已驳回组织的负责人可以重置密码，以便继续使用原有密码流程查看审核状态或重新提交资料；重置密码不授予短信登录资格，也不绕过组织审核。

重置成功后：

- 更新密码摘要；
- 递增 `sessionVersion`；
- 注销该账号在其他设备上的旧会话；
- 清除临时密码和 `mustChangePassword` 状态。

## 5. 方案选择

### 5.1 备选方案

方案一是在最终注册请求中直接提交短信验证码。改动最少，但组织资质校验、文件保存或数据库写入失败时，验证码可能已经被消费，用户需要重新发送。

方案二是先验证短信验证码，再签发短期手机号注册凭证。个人注册和组织注册最终提交该凭证。该方案把短信验证与较长的注册表单、文件上传解耦，失败后可以在凭证有效期内修正资料并重试。

方案三是把验证码消费、文件存储和业务账号创建纳入统一事务。它需要跨认证状态、业务数据库和文件系统协调事务，范围和复杂度明显超出本次需求。

### 5.2 采用方案

采用方案二：先验证手机号，再使用短期注册凭证完成注册。

## 6. 注册短信与注册凭证

### 6.1 新增短信用途

共享短信挑战服务新增不可变用途：

```text
sms-registration
```

该用途与 `sms-login`、`sms-password-reset` 在模板映射和验证码摘要中严格隔离。

### 6.2 注册验证码接口

新增：

```http
POST /api/auth/register/sms/request
Content-Type: application/json

{
  "phone": "13800000000",
  "captchaVerifyParam": ""
}
```

接口行为：

- 规范化并校验中国大陆 11 位手机号；
- 消耗手机号和 IP 限流额度；
- 在启用时验证注册场景的人机验证参数；
- 对所有合法格式手机号统一返回成功文案；
- 只有手机号尚未注册时才在后台生成并发送注册验证码；
- 已注册手机号、发送失败和资格变化不改变同步响应内容。

统一响应文案：

> 如果该手机号可用于注册，验证码将发送到该号码。

新增：

```http
POST /api/auth/register/sms/confirm
Content-Type: application/json

{
  "phone": "13800000000",
  "code": "123456"
}
```

验证码正确、未过期且手机号仍未注册时，返回注册凭证和明确过期时间。错误、过期、用途不匹配或状态变化统一返回“验证码无效或已过期”。

### 6.3 注册凭证格式

注册凭证是服务端签名的短期字符串，客户端必须把它当作不透明值处理。服务端采用无状态签名验证，不新增注册凭证表。内部载荷至少包含：

- 版本号；
- 用途 `sms-registration`；
- 规范化手机号；
- 签发时间；
- 过期时间；
- 随机 nonce。

凭证使用 HMAC-SHA256 签名。签名密钥从 `SESSION_SECRET` 通过固定的 `sms-registration-ticket:v1` 域分离派生，不能直接把会话 Cookie 或其他用途令牌当作注册凭证。

验证规则：

- 使用恒定时间比较验证签名；
- 有效期为 15 分钟；
- 用途必须为注册；
- 凭证手机号必须与最终注册请求手机号完全一致；
- 修改手机号、页面刷新或关闭页面后，前端丢弃凭证；
- 凭证不写入 `localStorage`、`sessionStorage`、Cookie 或日志；
- 手机号唯一约束是最终的一次成功注册边界；凭证在过期前允许修正失败的表单并重试，但不能成功创建多个账号；并发重复提交只能有一个成功，其余返回手机号已注册。

### 6.4 最终注册请求

个人注册 JSON 增加：

```json
{
  "name": "姓名",
  "phone": "13800000000",
  "password": "安全密码",
  "phoneVerificationToken": "短期注册凭证"
}
```

组织注册 multipart 表单增加：

```text
phoneVerificationToken=<短期注册凭证>
```

两个注册服务都必须在创建账号前验证凭证。缺少、过期、签名错误、用途错误或手机号不匹配时不能创建账号。现有密码强度、手机号唯一、统一社会信用代码唯一、文件类型、真实文件签名、文件大小和清理日志规则全部保留。

## 7. 前端流程

个人注册和组织注册共享相同的手机号验证交互：

1. 输入手机号；
2. 点击“获取验证码”；
3. 显示 60 秒重新发送倒计时；
4. 输入 6 位验证码并点击“验证手机号”；
5. 成功后显示“手机号已验证”，锁定手机号输入框；
6. 用户可点击“修改手机号”，该操作立即清空验证码和注册凭证；
7. 用户填写其余字段并提交；
8. 注册成功后返回登录页面。

组织负责人可以在手机号验证后填写组织资料和选择资质文件。服务端表单校验或文件校验失败时，只要 15 分钟注册凭证尚未过期且手机号未变，用户可以修正资料后重新提交，不需要再次发送短信。

页面刷新或关闭后，注册凭证丢失，用户必须重新验证手机号。

## 8. 验证码安全与限流

三个用途统一遵循：

- 6 位纯数字验证码；
- 5 分钟有效期；
- 最多 5 次错误尝试；
- 验证成功后一次性消费；
- 只保存 `HMAC-SHA256(purpose:phone:code)` 摘要；
- 同一手机号 60 秒发送冷却；
- 同一手机号每小时最多 5 条，三个用途合并计数；
- 同一 IP 每小时最多请求 20 次；
- 限流在账号查找和供应商调用前执行；
- 发送失败只清理本次摘要，不能删除后来发送的新挑战；
- 供应商调用和资格查找不阻塞统一 HTTP 响应；
- 日志不记录验证码、完整手机号、注册凭证或 AccessKey。

注册、登录和重置密码验证码不能跨用途消费。

## 9. 账户枚举与错误处理

### 9.1 统一发送响应

- 注册：`如果该手机号可用于注册，验证码将发送到该号码。`
- 登录和重置密码：`如果该手机号已注册，验证码将发送到该号码。`

不存在、已注册或状态不允许的手机号不调用阿里云发送接口，但响应正文和返回时机与允许手机号保持一致。

### 9.2 错误映射

- 手机号格式错误：`422`；
- 验证码错误、过期或用途不匹配：`422`；
- 注册凭证无效、过期或手机号不匹配：`422`，提示重新验证手机号；
- 请求过于频繁：`429`；
- 手机号在最终提交前已被注册：`409`；
- 对应短信功能未配置：`503`；
- 阿里云错误只写安全摘要日志，不向客户端暴露供应商响应、模板、账号或密钥信息。

## 10. 阿里云模板与供应商映射

使用现有签名：

```text
温州市少航科创中心
```

申请三个独立验证码模板：

### 10.1 注册模板

```text
您正在注册航空航天创新比赛平台账号，验证码为${code}，5分钟内有效，请勿泄露。
```

### 10.2 登录模板

```text
您正在登录航空航天创新比赛平台，验证码为${code}，5分钟内有效，若非本人操作请忽略。
```

### 10.3 重置密码模板

```text
您正在重置航空航天创新比赛平台账号密码，验证码为${code}，5分钟内有效，若非本人操作请忽略。
```

模板场景说明使用真实入口 `https://aerogp.cn/admin/`，分别说明个人/组织注册、既有账号登录和密码重置。模板审核结果与实际 Code 必须从阿里云控制台读取，不在代码中假设。

供应商映射：

```text
sms-registration     -> ALIYUN_SMS_REGISTRATION_TEMPLATE_CODE
sms-login            -> ALIYUN_SMS_LOGIN_TEMPLATE_CODE
sms-password-reset   -> ALIYUN_SMS_RESET_TEMPLATE_CODE
```

不得把旧通用模板作为缺失模板的自动回退。单个用途配置缺失时，只关闭该用途。

## 11. 功能开关与人机验证

`GET /api/public/features` 独立返回：

```text
smsRegistrationEnabled
smsLoginEnabled
smsPasswordResetEnabled
```

每个布尔值只在基础 AccessKey、签名和对应模板全部配置时为 `true`。任一用途缺少配置时失败关闭，不能影响其他用途或密码、邮箱通道。

可选人机验证增加注册场景：

```text
ALIYUN_CAPTCHA_SMS_REGISTRATION_SCENE_ID
```

公开功能信息在验证码启用时暴露注册场景 ID。`ALIYUN_CAPTCHA_ENABLED=false` 时不显示验证门禁，也不阻止短信流程；启用但配置不完整时失败关闭。

## 12. 环境变量与 Docker

服务器 `/opt/aerogp/.env` 增加或配置：

```text
ALIBABA_CLOUD_ACCESS_KEY_ID
ALIBABA_CLOUD_ACCESS_KEY_SECRET
ALIYUN_SMS_SIGN_NAME=温州市少航科创中心
ALIYUN_SMS_REGISTRATION_TEMPLATE_CODE
ALIYUN_SMS_LOGIN_TEMPLATE_CODE
ALIYUN_SMS_RESET_TEMPLATE_CODE
ALIYUN_CAPTCHA_SMS_REGISTRATION_SCENE_ID
```

`.env.example` 和 `compose.yaml` 只声明变量名和空默认值，不包含真实 AccessKey。部署脚本、测试输出、容器日志和版本接口不得输出秘密值。

## 13. RAM 最小权限

为生产服务器创建独立 RAM 程序用户，例如：

```text
aerogp-sms-sender
```

该用户只获得调用 `dysms:SendSms` 的自定义权限，不获得短信签名、模板、资质、账单、用户或其他云产品管理权限。不使用阿里云主账号 AccessKey。

AccessKey Secret 只在创建时写入 `server115` 的受保护环境文件，不进入聊天、剪贴板记录、Git、镜像层或部署日志。环境文件权限限制为仅部署管理员可读，并按运维策略轮换。

## 16. 回滚

短信功能按配置失败关闭。出现供应商、模板、报备或业务异常时：

1. 从服务器环境中清除对应模板 Code；
2. 重启 API 容器；
3. 验证对应公开功能开关为 `false`；
4. 保留密码登录、邮箱找回和管理员后台重置；
5. 如代码本身异常，恢复上一生产版本和部署配置；
6. 数据库和现有账号不需要回滚，因为短信登录不改变账号密码，注册仍遵守现有账号结构。

## 17. 验收标准

1. 个人账号和组织负责人账号没有短信验证不能注册。
2. 管理员没有公开注册入口。
3. 启用的管理员可以短信登录和短信重置密码。
