# 官网内容发布流程优化设计

## 1. 背景与问题

管理员在“官网内容 → 内容发布”中维护新闻、通知、规程、优秀作品和赛事回顾。目前页面同时展示内容列表和一张空白“新建内容”表单，即使管理员尚未点击新建，也容易误以为必须立即填写；在窄屏下列表与表单上下堆叠，操作目标更不清楚。

当前还存在两个直接影响使用的问题：

1. 富文本正文输入时会被反复更新 DOM，导致光标或焦点丢失，需要重新点击编辑区才能继续输入。
2. “赛事视觉”允许勾选“在官网公开此赛事”，但没有充分说明业务赛事是否已经发布；草稿赛事即使勾选，也不会真正出现在公共官网，容易造成“已公开”的误判。

本设计采用已经确认的 **A 方案：内容列表与内容编辑分开**，在保留现有能力的前提下，重新整理管理员的任务顺序、状态反馈和发布检查。

## 2. 目标

- 默认只展示内容列表，管理员先搜索、筛选、查看状态，再决定新建或编辑。
- 点击“新建内容”或“编辑”后进入独立编辑视图，不再同时显示列表和空表单。
- 保留归属赛事、内容类型、摘要、富文本正文、图片、附件、公开地址、状态、排序、置顶、预览、定时展示等现有能力。
- 新建内容默认保存为草稿；保存、预览和发布的结果清晰可见。
- 修复富文本输入期间的光标和焦点丢失问题。
- 将赛事业务状态与官网公开状态明确联动，避免草稿赛事被误认为已经公开。
- 适配管理端常见桌面宽度和窄屏，不让编辑区与内容列表混在同一长页面中。

## 3. 非目标

- 不改变公共官网的视觉风格和内容详情页布局。
- 不删除或减少现有内容字段、内容类型和发布能力。
- 不在本期引入多人协作、审批流、版本对比或定稿工作流。
- 不改变数据库中现有内容与赛事的主业务状态含义。
- 不自动发布赛事或内容，也不根据勾选操作替管理员执行跨模块发布。

## 4. 总体交互结构

“内容发布”标签使用一个页面、三个明确视图：

1. **内容列表**
2. **专注编辑**
3. **预览与发布检查**

三个视图通过页面内部状态或稳定路由参数切换，但同一时刻只展示一个主任务。刷新页面时：

- 若 URL 或页面状态中存在合法内容 ID，则恢复该内容的编辑视图。
- 若没有合法编辑对象，则回到内容列表。
- 未保存的新建表单不写入数据库；刷新前必须使用离开提醒降低误丢失风险。

## 5. 内容列表视图

### 5.1 默认状态

进入“内容发布”时只显示：

- 页面标题与简短说明；
- “新建内容”主按钮；
- 搜索与筛选；
- 内容列表；
- 刷新按钮和分页信息。

不再默认挂载空白的新建表单。

### 5.2 搜索与筛选

保留并统一以下条件：

- 关键词：标题、公开地址、摘要或关联赛事；
- 内容状态：全部、草稿、定时发布、已发布、已下线；
- 归属赛事：平台通用或具体赛事；
- 内容类型：新闻、通知、规程、优秀作品、赛事回顾等现有枚举。

筛选变化后回到第一页。提供“清空筛选”，刷新只重新读取数据，不重置管理员已经选择的筛选条件。

### 5.3 列表信息

每一条内容至少显示：

- 标题；
- 内容类型；
- 归属赛事；
- 当前状态；
- 置顶或定时信息；
- 最近更新时间；
- 编辑入口；
- 已发布内容的官网预览入口。

状态使用文字和颜色共同表达，不能只依赖颜色。

### 5.4 空状态

没有任何内容时显示：

- “尚未创建官网内容”；
- 对内容用途的简短解释；
- “新建第一篇内容”按钮。

筛选无结果时显示“没有符合条件的内容”，同时提供“清空筛选”，不显示新建表单。

## 6. 专注编辑视图

### 6.1 顶部导航

编辑视图顶部显示：

- “返回内容列表”；
- 面包屑：内容管理 / 新建内容或内容标题；
- 当前保存状态：未保存、保存中、已保存、保存失败；
- 草稿或已发布状态标识。

从存在未保存修改的编辑视图返回列表、切换管理菜单、刷新或关闭页面时，必须提示管理员确认。

### 6.2 字段分组

编辑表单仍为单页，但按任务分成三个编号区域。

#### 1. 基本信息

- 标题（必填）；
- 归属赛事；
- 内容类型（必填）；
- 公开地址 slug；
- 摘要；
- 现有业务要求的其他基础字段。

公开地址默认根据标题生成。管理员手动修改后，不再因标题变化被自动覆盖；编辑已发布内容时保持现有稳定 slug 规则。

#### 2. 正文与媒体

- 富文本正文；
- 正文图片；
- 封面；
- 附件；
- 现有图片和附件的删除或替换。

图片和附件应显示上传中、上传成功、失败和可重试状态。删除已保存资源时沿用现有权限与引用规则。

#### 3. 展示与发布设置

- 内容状态；
- 发布时间或定时展示时间；
- 排序；
- 置顶；
- 现有展示控制字段。

新建内容默认状态为“草稿”。保存草稿不要求满足所有公开字段，但发布前必须完成发布校验。

### 6.3 底部固定操作区

编辑视图底部保持可见的操作区：

- 保存草稿；
- 保存并预览；
- 进入发布检查；
- 编辑已发布内容时显示与当前状态相符的更新操作。

按钮在请求期间禁用重复提交，并显示处理中状态。保存失败不能清除表单内容。

## 7. 富文本输入修复

### 7.1 根因

当前编辑器在每次输入事件后把编辑区 HTML 回写到响应式值，随后框架再次把该值写回 `contenteditable` 的 `innerHTML`。这个循环会让浏览器选择区和光标位置失效，表现为输入一段文字后必须重新点击编辑区。

### 7.2 修复原则

- 编辑器获得焦点并输入时，以浏览器当前 DOM 和选择区为主，不在每个按键后重设 `innerHTML`。
- 输入事件只向父组件发出规范化后的新值，不主动重建当前编辑 DOM。
- 只有外部值真正发生变化且与当前编辑 DOM 不一致时，才同步 `innerHTML`。
- 外部同步发生在编辑器未聚焦时；若编辑器正在聚焦，延迟到失焦或显式切换内容对象时处理。
- 切换到另一篇内容时重置编辑器状态和历史，不把上一条内容的选择区带入新内容。
- 继续使用现有富文本安全过滤规则；修复焦点不能降低 XSS 和危险链接防护。

### 7.3 编辑器体验

- 点击一次正文区域即可连续输入中文、英文、数字和换行。
- 使用标题、加粗、斜体、列表、链接、引用和插图后，光标留在合理位置。
- 从 HTML 或纯文本模式切回可视化模式时，内容不丢失。
- 浏览器输入法组合输入期间不能中途回写 DOM。

## 8. 预览与发布检查

“保存并预览”或“进入发布检查”后，使用已确认的官网预览能力，在新标签或受控预览页展示当前草稿，不写入公开状态。

发布检查至少显示：

- 标题、摘要、正文和媒体是否完整；
- 内容类型和归属范围；
- 公开地址；
- 置顶与排序；
- 当前内容状态；
- 关联赛事的业务状态与官网公开状态；
- 发布后实际结果。

只有发布校验通过时才允许“确认发布”。校验失败时定位到对应分组并提供可执行说明。

## 9. 内容状态规则

### 9.1 新建内容

- 默认：草稿；
- “保存草稿”：只保存，不公开；
- “保存并预览”：保存或生成安全草稿预览，不公开；
- “确认发布”：校验成功后进入已发布或现有定时发布状态。

### 9.2 平台通用内容

不关联具体赛事的内容按照自身状态决定是否公开。其发布不依赖某一场赛事的业务状态。

### 9.3 关联赛事的内容

- 赛事为草稿：内容可以保存为草稿和预览，但不能让管理员误以为已经在官网公开；发布检查显示“归属赛事尚未发布”，并提供“去赛事设置”入口。
- 赛事已发布且官网公开：内容满足自身发布条件后可正常公开。
- 赛事已发布但官网隐藏：明确提示内容可能无法从赛事入口被访问；管理员可以保存内容，但发布前必须确认实际展示范围。
- 赛事已归档：内容按历届赛事规则展示，并标注“将显示在历届赛事”。

系统不自动修改关联赛事的状态或公开开关。

## 10. 赛事视觉的公开状态提醒

赛事视觉页根据业务赛事状态显示以下状态：

| 业务赛事状态 | 官网公开开关 | 管理端提示 | 公共结果 |
| --- | --- | --- | --- |
| 草稿 | 禁用 | “当前赛事仍是草稿，请先到赛事设置发布” | 不公开 |
| 已发布 | 关闭 | “业务赛事已发布，但官网尚未公开” | 不公开 |
| 已发布 | 开启 | “官网已公开” | 当前赛事可见 |
| 已归档 | 关闭 | “已归档且未在历届赛事展示” | 不公开 |
| 已归档 | 开启 | “将在历届赛事中展示” | 历届赛事可见 |

具体规则：

- 草稿赛事的“在官网公开此赛事”开关禁用，并显示“去赛事设置”。
- 保存赛事视觉后显示结果提示，不能只显示“设置已保存”。
- 状态标签同时展示业务状态与官网状态，例如“业务：已发布 / 官网：隐藏”。
- 赛事业务状态由“赛事设置”维护，赛事视觉页只维护官网展示字段。

## 11. 响应式与可访问性

- 桌面端编辑区使用单列主内容和适度的双列字段，不再同时显示左侧内容列表。
- 窄屏下字段自动变成单列，底部操作区允许换行或收拢为主按钮加更多菜单。
- 返回、保存、预览、发布和错误提示都可通过键盘操作。
- 输入标签与表单控件正确关联；状态和错误使用文本说明。
- 发布确认对话框的默认焦点和按钮顺序明确，避免误发布。

## 12. 错误与恢复

- 列表加载失败：保留筛选条件，显示重试。
- 内容加载失败：不显示空编辑器覆盖错误，提供返回列表和重试。
- 保存失败：保留所有表单值，标记未保存并提供再次保存。
- slug 冲突：定位公开地址字段，给出可用建议。
- 图片或附件失败：只标记对应资源，不阻止继续编辑其他字段。
- 发布校验失败：不改变内容当前状态，并跳转到第一个错误分组。
- 会话失效：提示重新登录；在安全允许范围内保留本地未提交表单，避免静默丢失。

## 13. 数据与接口影响

- 不新增数据库表。
- 继续使用现有内容、媒体和赛事公开资料接口。
- 管理端列表、详情、创建、更新、发布和预览请求保持职责分离。
- API 继续作为最终权限和发布校验边界；前端禁用按钮不能替代服务端校验。
- 若现有内容接口允许把关联草稿赛事的内容标记为已发布，API 必须返回明确的实际可见性信息，前端据此展示“已发布但暂不可见”，避免伪成功。

## 14. 测试与验收

### 14.1 内容列表

- 初次进入只显示列表，不出现空白新建表单。
- 新建和编辑分别进入独立编辑视图。
- 搜索、状态、赛事和类型筛选正确组合，刷新保留筛选。
- 空列表与筛选无结果显示不同引导。

### 14.2 编辑与保存

- 新建内容默认草稿，所有现有字段仍可编辑。
- 返回列表和切换菜单遇到未保存修改会提醒。
- 保存中不能重复提交，失败后表单内容不丢失。
- slug 自动生成和人工修改规则保持稳定。

### 14.3 富文本

- 连续输入至少 200 个中英文字符无需重新点击编辑区。
- 中文输入法组合输入不跳光标、不丢字、不重复字符。
- 工具栏格式、粘贴、撤销重做和模式切换后内容正确。
- 外部加载另一篇内容时编辑器更新且不残留上一条内容。
- 安全过滤相关测试继续通过。

### 14.4 发布与赛事状态

- 草稿内容不会出现在公共官网。
- 发布前检查显示内容和赛事的实际状态。
- 草稿赛事的官网公开开关禁用，并提供“去赛事设置”。
- 已发布赛事的公开开关保存后显示“官网已公开”或“官网隐藏”。
- 已归档赛事开启公开后只进入历届赛事范围。
- 平台通用内容不被某场赛事状态错误阻止。

### 14.5 响应式

- 在 360px、768px、1024px 和 1440px 宽度下，列表、编辑与发布检查均可完成。
- 窄屏不会再次出现列表和整张编辑表单上下混合的长页面。
- 固定操作区不遮挡最后一个字段和错误提示。

## 15. 发布与回退

1. 先发布富文本输入修复及其测试。
2. 再发布内容列表与独立编辑视图，保留原接口和数据结构。
3. 最后启用发布检查和赛事状态联动提示。
4. 上线后重点观察保存失败率、发布校验失败率和富文本前端错误。

若出现问题，可将“内容发布”切回旧页面结构；数据库与公共接口没有破坏性迁移，已保存内容不受影响。富文本修复可独立回退，但回退前应保留新增测试以确认问题是否重新出现。

## 16. 完成标准

管理员能够：

1. 在内容列表中清楚地查找、筛选、新建或编辑内容；
2. 在独立编辑视图中完成全部现有字段，而不与列表混在同一页面；
3. 连续输入正文，不再反复点击左键恢复光标；
4. 保存草稿、预览和发布，并明确知道每个动作是否会影响官网；
5. 在赛事视觉和内容发布检查中看到业务赛事状态与官网公开状态；
6. 不会因勾选草稿赛事的公开开关而误以为赛事已经上线。
